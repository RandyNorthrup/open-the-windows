## Honest deviations and follow-ups

None of these is a broken feature; each is a safe, documented limitation.

- **Offline `Software\Classes` (UsrClass.dat).** A user's `Software\Classes`
  subtree is backed by `UsrClass.dat`, which a force-loaded `NTUSER.DAT` does not
  carry. Rather than write it into the wrong hive and falsely report success, an
  all-users apply marks such an action `NotApplicable` for a hive it had to
  force-load (an offline user); logged-on users, whose `Software\Classes` is live,
  apply it normally. Five `shell.explorer.*` CLSID entries are affected. Full
  offline `UsrClass.dat` support (loading it alongside `NTUSER.DAT`) is a follow-up.
- **Hive that cannot be loaded.** If an offline hive cannot be loaded (a sharing
  violation because the user signed in mid-run, or a locked hive), the all-users
  apply fails and rolls back — safe, but not the graceful per-user skip the spec
  describes. Graceful skip-and-report is a follow-up.
- **Active Setup per-user execution.** The component registration is VM-verified.
  Windows running the stub in each user's own session at their next sign-in is the
  standard Active Setup contract; it is not exercised here because a headless SSH
  session cannot drive a brand-new user's interactive first logon.
- **Interactive-user resolution over headless SSH.** Two integration checks
  (`Interactive_user_resolves_to_the_session_user`, `Resolves_the_signed_in_user`)
  return null in session 0 and are expected to fail over headless SSH; they pass in
  a real console session. Unchanged since M4.
