## Accessibility manual check

- **AutomationId coverage** — 73 stable `AutomationId`s across the ten views and
  the shell, all of the form `<Page>_<Element>` (`Nav_<Page>` for navigation);
  17 non-text controls (combo boxes, search boxes, lists) carry an explicit
  `AutomationProperties.Name`, and buttons / checkboxes derive their name from
  their text content.
- **Colour is never the only signal** — risk tiers show a coloured accent
  **and** the risk word; the managed/updates read-only state shows a banner with
  text; end-of-servicing shows the date and a worded warning.
- **DPI** — the app manifest declares per-monitor-DPI-v2 (and long-path / UTF-8
  awareness).
- **Theme / contrast** — the app follows the WPF Fluent theme, which tracks the
  system light / dark / high-contrast setting; banners and borders use
  `SystemColors` brushes so they invert with the theme; the theme can also be
  pinned in Settings (applied live).
- **Keyboard & focus** — Tab order and visible focus use the WPF defaults; the
  navigation list is arrow-key traversable; the M0 `CanApply` "True/False"
  defect is fixed (a `BoolToYesNoConverter` shows "Yes"/"No").
- **Fix from M0** — verified: `CanApply` surfaces as "Yes"/"No"
  (`BoolToYesNoConverterTests`).

## FlaUI smoke

`build/ui-smoke.ps1` is the GUI smoke harness: it publishes the app self-contained,
re-launches itself elevated, restores FlaUI/UIA3 5.0.0, attaches to the window,
clicks each navigation item by its `Nav_<Page>` AutomationId, captures a
screenshot of each page to `docs/certification/M6/<Page>.png`, and measures cold
start against a 2-second budget.

It was **not run autonomously in this environment**, for the same reason M5's
interactive-user checks could not run over SSH: UI automation drives real
windows and needs an **interactive, elevated desktop session**. The lab VM is
reached over headless SSH (Windows session 0, which has no interactive desktop),
and the only interactive Windows desktop available is the developer's own live
session, where launching an elevated, self-driving GUI would disturb the user.
Run `pwsh build/ui-smoke.ps1` from an elevated console on the machine under test
to produce the screenshots and cold-start figure.

What is verified without the rendered drive: the app builds and publishes
self-contained; the shell resolves and navigates to every page
(`ServiceGraphTests`); and the apply/revert engine the GUI drives is VM-verified
at M5.

## Performance

- **Cold start < 2 s** — measured by the Stopwatch in `build/ui-smoke.ps1`
  (interactive run required, as above).
- **500-entry list virtualised** — the category and history lists set
  `VirtualizingPanel.IsVirtualizing="True"` with recycling and
  `ScrollViewer.CanContentScroll="True"`.
- **No UI freeze during apply** — apply, revert, pause and resume run on the
  thread pool (`Task.Run` in the coordinators); results are marshalled back by
  awaiting on the UI context.

## Honest deviations and follow-ups

None of these is a broken feature; each is a safe, documented limitation.

- **FlaUI page-by-page smoke** — the harness is complete but was not executed
  here (no non-intrusive interactive elevated desktop; see above). Screenshots
  are produced by an interactive run.
- **Scan-driven drift / managed badges on the category pages** — the category
  pages present the catalogue and the level dial; live per-entry drift and the
  managed padlock (which need a full scan of each category on show) are a
  follow-up. The apply flow already reports each entry's current compliance in
  its what-if preview, and managed entries are planned `Managed` and skipped by
  the engine, so applying is safe without the badge.
- **Per-entry revert** — the History page reverts a whole run (the engine's
  transactional unit). Reverting a single entry of a run is a follow-up.
- **Settings persistence** — settings are session-scoped in M6; persisting them
  across launches is a follow-up.
- **Enterprise-mode consumer set** — enterprise mode hides the `home` and
  `gamer` built-ins (the consumer presets); this list is a product decision
  (spec Q2, now resolved: enterprise mode hides consumer profiles).
