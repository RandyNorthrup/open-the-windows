  **verify-failure rollback**, **journal-written-before-first-write** (trace

## Security

- Journal directory ACL (Administrators/SYSTEM full, creator full, Users read)
  applied on creation; the store round-trips through a real temp directory in
  `WindowsJournalStoreTests`.
- No write without a journal: the engine writes the journal (with every prior)
  before the first change — asserted by the write-before-change trace-ordering
  test (fault injected on the first write).
- `Process` is confined to `WindowsCommandRunner`: `ReadOnlyArchitectureTests`
  fails if any other `src/` file suppresses the RS0030 ban.
- Break-glass over a managed setting emits Event 4001 and journals `breakGlass:true`.

## VM runs

Windows 11 Pro 25H2 (26200.9168), elevated (`win-11-vm\randy`). Published
self-contained `otw.exe` (`PublishTrimmed=false`) and self-contained test build.
Journals under `%ProgramData%\OpenTheWindows\journal`; audit to the
`OpenTheWindows` Event Log + JSONL. The machine-policy round-trip passed; the
full-profile CLI apply exercised the atomic rollback path on real Draft-entry
failures; the VM was cleaned afterwards (registry, ProgramData, test folder,
`gpupdate /force`).

## Deviations

- **Per-user hive apply is not demonstrated over the headless SSH session** used
  for VM automation: the interactive-user resolver correctly returns `null` when
  there is no console session, so per-user writes are safely refused and the run
  rolls back. Per-user hive writes are covered by the unit tests and work from a
  real desktop session; the VM acceptance therefore uses a machine-scope policy
  value. A console-session fallback for the resolver is an M5 refinement.
- **Optional features** use the in-box `dism.exe` via the guarded command runner
  rather than a hand-rolled DISM API binding (PLAN.md §8).
- **Mutation gate DEFERRED** (Stryker/MTP, stryker-net#3094).
