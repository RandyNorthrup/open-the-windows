## Deviations (honest, and why)

- **WiX 5, not WiX 7.** WiX 6/7 refuse to build without accepting FireGiant's paid
  Open Source Maintenance Fee EULA (error `WIX7015`). WiX 5 is the last fee-free
  line and produces an equivalent MSI, keeping the toolchain free and
  MIT-compatible (ADR 0003). The `installer/` project is SDK-style
  (`WixToolset.Sdk/5.0.2`).
- **No pinned `wix` dotnet tool.** The SDK-style project restores `WixToolset.Sdk`
  from NuGet, so a globally-pinned `wix` tool (as the spec suggested) would be
  unused tooling; it was intentionally not added.
- **`REMOVEDATA=1` removed.** The spec asked for an uninstall switch to purge the
  data folder. MSI component install-state cannot be driven by an uninstall-time
  property, so the switch never purged in VM testing — and, more importantly, a
  silent flag that wipes the audit trail of an elevated security tool
  (`msiexec /x … REMOVEDATA=1 /qn`) is a liability. The MSI now always preserves
  `%ProgramData%\OpenTheWindows`; removing it is a documented manual step. This
  also dropped the unused `WixToolset.Util.wixext` dependency.
- **Home image not tested.** Only a Pro 25H2 VM is available in the lab. Install,
  upgrade and uninstall are edition-independent for this MSI (no edition-gated
  components), but that is reasoning, not a run on Home.
- **Attestations and the release workflow are authored, not executed.** The
  standing project directive keeps everything local until the whole project is
  certified, so nothing is pushed and no CI/tag run happens yet. `release.yml` is
  SHA-pinned, actionlint-clean and semgrep-clean (untrusted trigger context read
  through `env:`); `gh attestation verify` and a green tag run will be exercised
  when the project is pushed.
- **Reproducibility not measured across two CI builds.** `Deterministic` is on, but
  `ContinuousIntegrationBuild` only activates under CI (`CI=true`), and the
  single-file self-contained bundles are not expected to be byte-identical locally.
  The two-CI-build hash comparison is deferred to the first real CI run.

## Product finding surfaced by packaging

Publishing the CLI single-file with trimming (`PublishTrimmed=true`) was broken:
the reflection-based Windows interop (`System.Management`/WMI, `TaskScheduler`,
WinRT/Appx) produced `IL2104` trim warnings that became `NETSDK1144` under
warnings-as-errors — and, had it linked, trimming could have removed members the
tool reaches only by reflection. The CLI now publishes single-file self-contained
but **untrimmed** (~100 MB); the framework-dependent ZIP (~18 MB) is the small
alternative. `build/publish.ps1` (the CI publish smoke) was updated to match.

## Artifacts (produced by `build/package.ps1`)

For each runtime: a self-contained portable ZIP (~112 MB x64) and a per-machine
MSI (~92 MB x64), plus a framework-dependent x64 ZIP (~18 MB), a CycloneDX SBOM
(`sbom.cdx.json`) and `SHA256SUMS.txt`. `build/winget-manifest.ps1` generates the
winget multi-file manifest (schema 1.6.0) from the built MSIs.
