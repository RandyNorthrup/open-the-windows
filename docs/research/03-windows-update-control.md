## 1. Executive summary

* **Windows Update cannot be "turned off" safely, and OTW must not try.** The only supported, reversible, edition-appropriate controls are: (1) the Settings-app **pause** (35 days; the same registry values the UI writes), (2) **Windows Update client policies** (formerly "Windows Update for Business", WUfB) — deferral (feature ≤365 d, quality ≤30 d), policy-pause (35 d from a start date), **TargetReleaseVersion / ProductVersion** feature-update pinning, driver exclusion, optional-content behaviour, preview-build management, (3) **Automatic Updates (AU) behaviour** (`AUOptions` 2/3/4 = notify / auto-download-notify / scheduled), (4) **restart controls** — active hours, compliance deadlines + grace periods, notification level, the new (Jan 2026, 24H2+) **maintenance windows**, (5) **Delivery Optimization** download mode / bandwidth caps, (6) **per-update hiding** through the Windows Update Agent (WUA) COM API (`IUpdate.IsHidden`) as a replacement for the dying `wushowhide.diagcab`, and (7) adjacent updaters (Store auto-update policy, Edge Update policies, Office C2R policies, .NET `BlockMU`, MSRT `DontOfferThroughWUAU`).
* **Explicitly refuse to implement** (see §7.3): disabling/ACL-hijacking `WaaSMedicSvc`, `wuauserv`, `UsoSvc`, `DoSvc`, `BITS`, `TrustedInstaller`; deleting or ACL-locking UpdateOrchestrator/WaaSMedic scheduled tasks; `NoAutoUpdate=1` / `AUOptions=1` "kill switch" presets; `DoNotConnectToWindowsUpdateInternetLocations` outside a WSUS scenario; `DisableWindowsUpdateAccess`; `DisableWUfBSafeguards` (only behind an "IT validation" advanced mode with a warning); taking ownership of `NetworkList\DefaultMediaCost` to fake a metered Ethernet; hosts/firewall blocking of `*.windowsupdate.com` / `*.update.microsoft.com` / `*.delivery.mp.microsoft.com`; anything that blocks **Defender security-intelligence updates**; multi-year "pause until 2051" registry hacks as a one-click preset.
* **Home vs Pro (one paragraph):** Windows 11 Home has the Settings-app controls only: Pause updates (up to 35 days, "Pick a date" calendar), Active hours (manual or "automatically adjust"), "Get the latest updates as soon as they're available", "Receive updates for other Microsoft products", metered-download toggle, restart notification toggle, Optional updates page and Delivery Optimization page. Every policy in the *Update* Policy CSP — deferrals, policy pause, TargetReleaseVersion, ExcludeWUDriversInQualityUpdate, AllowAutoUpdate/AUOptions, active-hours policy, deadlines, notification level, DisableWUfBSafeguards, ManagePreviewBuilds, AllowOptionalContent, WSUS pointing, SetDisableUXWUAccess/SetDisablePauseUXAccess — is documented by Microsoft as **Pro / Enterprise / Education / IoT Enterprise only** ("Home: No"), and Home ships no `gpedit.msc`. Widespread community reports say that some of the raw `HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate` values (notably `AUOptions`, `TargetReleaseVersion*`, `ExcludeWUDriversInQualityUpdate`) are honoured on Home too, but Microsoft does not document or support that; OTW must treat those as **UNVERIFIED / best-effort on Home**, verify by reading back the effective state (`HKLM\SOFTWARE\Microsoft\WindowsUpdate\UpdatePolicy\PolicyState`, `UpdatePolicy\Settings`, WUA API), and never *promise* the result on Home. Enterprise/Education additionally get 36-month servicing per release (24 months on Home/Pro), Temporary Enterprise Feature Control (new features stay off by default), Windows Autopatch (Business Premium/A3+/E3+/F3), and hotpatching (Enterprise 24H2+ via Autopatch).
* **Time-critical fact for the app:** as of today Windows 11 **23H2 Home/Pro is already out of support (EOS 2025-11-11)** and **24H2 Home/Pro reaches EOS on 2026-10-13 — 58 days from now**; Enterprise/Education 24H2 runs to 2027-10-12, 25H2 Home/Pro to 2027-10-12, 25H2 Ent/Edu to 2028-10-10, 23H2 Ent/Edu to 2026-11-10 (§4.2). Any "stay on 24H2" pin OTW writes for a Home/Pro device today must ship with a red warning; the recommended default is a **90-day pre-EOS warning** plus a hard "EOS reached" alert that offers to clear the pin.
* **Recommended guardrails (short list; full list in §7.2):** cap pause at 35 days by default with an explicit "extend beyond Microsoft's limit" override that requires acknowledging a security warning and never exceeds a configurable ceiling (suggest 90 days); always keep Defender security-intelligence updates flowing (never block `Definition Updates`, never point Defender fallback order away from `MicrosoftUpdateServer|MMPC`); a one-click **"Resume updates now"** panic button that clears every pause/defer/pin the app wrote and triggers a scan (`UsoClient StartScan` / WUA `IUpdateSearcher`); a live **update-status dashboard** (last scan/install success, pending reboot, paused-until, effective policies and their source, days to EOS); detect **MDM / WSUS / Autopatch / Group Policy management** and switch the whole category to read-only "managed by your organization" mode instead of fighting the management authority; write only documented policy values and only in the documented locations; snapshot before/after and expose one-click revert; log every change to the Event Log.

## 2. Method and verification legend

* Primary sources are `learn.microsoft.com` (Windows Update client policies, Policy CSP – Update, Delivery Optimization reference, WUA API reference, release-health lifecycle table, Defender update docs, Edge/Office/.NET update docs) and Microsoft ADMX files (`WindowsUpdate.admx`, `WindowsStore.admx`, `DeviceSetup.admx`, `ICM.admx`) whose registry value names were read directly from a copy of the Windows 11 `WindowsUpdate.admx`. Community sources (ElevenForum, WOSHub, Patch My PC, GitHub tools) are used only for undocumented registry values written by the Settings app, and are labelled as such.
* Where a value name could be checked on a live Windows 11 machine (build 22621, Pro, unmanaged) during research, that is stated ("observed locally"). Local observation verifies *existence/shape*, not semantics.
* Legend used in tables: **DOC** = documented by Microsoft; **ADMX** = value name taken from Microsoft ADMX; **COMMUNITY** = undocumented, community-verified; **UNVERIFIED** = plausible but not confirmed by a Microsoft source or local test; **LEGACY** = Microsoft marks the policy "legacy and isn't applicable for Windows 11; might be removed".
* Registry type abbreviations: `DW` = REG_DWORD, `SZ` = REG_SZ. `HKLM\...\Policies\...\WindowsUpdate` is written as **`[POL]`**, `HKLM\...\Policies\...\WindowsUpdate\AU` as **`[POL\AU]`**, `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings` as **`[UX]`**, `HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\Update` (MDM) as **`[MDM]`**.

## 3. Primer: how the Windows 11 update stack works (what OTW is touching)

* **Services.** `wuauserv` (Windows Update Agent, `wuaueng.dll`, host of the WUA COM API), `UsoSvc` (Update Session Orchestrator — schedules scan/download/install/reboot via `usoclient.exe` and the `\Microsoft\Windows\UpdateOrchestrator\*` tasks), `WaaSMedicSvc` (Windows Update Medic — self-heals the update stack: re-enables services/tasks, repairs registry/ACL damage; runs as a **protected-process-light service** — `LaunchProtected = 2` observed locally — which is why admins get *Access denied* when trying to stop/disable it), `BITS` (legacy transfer; DO falls back to it), `DoSvc` (Delivery Optimization — the actual downloader for WU, Store, Defender, Edge, Office C2R content), `TrustedInstaller` (Windows Modules Installer / CBS — installs the payload), `cryptsvc` (catalog store `catroot2`), plus the **Unified Update Stack (UUS/UUP)** components that arrive with each cumulative update.
* **Update classes** the policies distinguish: *feature updates* (annual, e.g. 24H2→25H2, delivered as enablement package when possible), *quality updates* (monthly "B" cumulative security release, optional "D" non-security preview, out-of-band), *driver updates* (WU-published, classified as "Driver"), *definition/security-intelligence updates* (Defender, several per day), *other Microsoft products* (via the Microsoft Update service — .NET, SQL, Office MSI, Visual Studio…), *optional content* (features rolled out gradually = Controlled Feature Rollouts, "CFR"), *Insider preview builds*, and *Store/winget/Edge/Office C2R* which use their own updaters, not `wuauserv`.
* **Where policy comes from, in precedence order (roughly):** MDM (`PolicyManager`) ≥ Group Policy (`HKLM\SOFTWARE\Policies\...`) > Settings-app preferences (`[UX]`, HKCU/HKU) > defaults. The WU client materialises the *effective* result under `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UpdatePolicy\PolicyState` (values observed locally: `IsWUfBConfigured`, `IsWUfBDualScanActive`, `BranchReadinessLevel`, `DeferFeatureUpdates`, `DeferQualityUpdates`, `IsDeferralIsActive`, `UseUpdateClassPolicySource`, `SetPolicyDrivenUpdateSourceFor*`, `TemporaryEnterpriseFeatureControlState`) and pause status under `UpdatePolicy\Settings` (`PausedFeatureStatus`, `PausedQualityStatus`, `PausedFeatureDate`, `PausedQualityDate` — documented). This is the key OTW should read for the dashboard.
* **Compliance deadlines and Medic exist because unpatched Windows is Microsoft's #1 fleet risk.** Every "disable updates" hack fights an engine explicitly designed to undo it; the practical result is either (a) it silently stops working after the next cumulative update, or (b) it works and the machine stays unpatched with a broken servicing stack. Both are unacceptable for a tool that calls itself enterprise-grade.

### 4.3 23H2 vs 24H2 vs 25H2 differences that matter for update control

* **Maintenance-window policies** (`MaintenanceWindow*` in Update CSP / GP) — 24H2 and later with the January 2026 non-security update; not on 23H2.
* **Compliance-deadline behaviour** — since the December 10, 2024 update (22H2+), *Configure Automatic Updates* is respected before the deadline and ignored after it; deadline calculation starts from scan discovery time (22H2+ policies `ConfigureDeadlineNoAutoRebootForFeatureUpdates` / `...ForQualityUpdates`, `ConfigureDeadlineGracePeriodForFeatureUpdates` are 22H2+ only).
* **`AllowOptionalContent`** — Windows 11 22H2 with KB5029351 and later (so all three targets).
* **"Fix problems using Windows Update" (repair reinstall from Settings › System › Recovery)** — Windows 11 22H2+ (2024 CU); unavailable on managed devices.
* **Pause UI** — "Pick a date" calendar (rolling out 2025) replaces the 1–5-week dropdown; the community `FlightSettingsMaxPauseDays` trick reportedly does not apply to the calendar UI (COMMUNITY).
* **Store auto-update UI** — since mid-August 2025 the Store client offers *pause 1–5 weeks* instead of a permanent Off toggle (policy `AutoDownload=2` unaffected).
* **MSDT / `.diagcab` deprecation** — MSDT deprecated Jan 2023, removal under way in 2025 builds; `wushowhide.diagcab` is unreliable on 24H2/25H2 → OTW should implement hiding natively via WUA (§5.9).
* **26H1** exists but is out of scope (OEM-only; not an in-place target).

## 5. Mechanism catalogue

### 5.1 Settings-app "Pause updates" (`[UX]` = `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UX\Settings`)

* **What the UI does.** Settings › Windows Update › *Pause updates* › **Pick a date** (or the older *Pause for 1 week* ×5). Microsoft: "You can pause for up to 35 days from the current date… After the pause ends, your device will check for, download, and install the latest available updates… If updates are in progress when you pause updates, those updates are canceled." Pausing through Settings also (documented for 1703+): clears active restart notifications, cancels pending restarts and pending installations, and attempts to roll back an in-flight installation.
* **Registry values written (COMMUNITY, consistent across ElevenForum / WOSHub / Aetherinox tool; not on the local unpaused test machine):** all `SZ` in ISO-8601 UTC `yyyy-MM-ddTHH:mm:ssZ`:
  `PauseUpdatesStartTime`, `PauseUpdatesExpiryTime` (the "paused until" the UI shows), `PauseFeatureUpdatesStartTime`, `PauseFeatureUpdatesEndTime`, `PauseQualityUpdatesStartTime`, `PauseQualityUpdatesEndTime`. Resuming clears/blanks them. Status mirrors in `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UpdatePolicy\Settings`: `PausedFeatureStatus`, `PausedQualityStatus` (`DW`: 0 not paused, 1 paused, 2 auto-resumed — DOC), `PausedFeatureDate`, `PausedQualityDate` (DOC).
* **Other `[UX]` values observed locally / reported:** `ActiveHoursStart`, `ActiveHoursEnd` (`DW` 0–23, manual active hours), `SmartActiveHoursStart`, `SmartActiveHoursEnd`, `SmartActiveHoursSuggestionState` (observed; the "Automatically adjust active hours" state — exact semantics UNVERIFIED; community says `SmartActiveHoursState` 1 = automatic, 2 = manual on some builds), `AllowAutoWindowsUpdateDownloadOverMeteredNetwork` (`DW`, observed; the metered toggle), `ExcludeWUDriversInQualityUpdate` (`DW`, observed even on an unmanaged Pro machine — semantics UNVERIFIED), `FlightSettingsMaxPauseDays` (`DW`, absent by default; COMMUNITY: creates a higher UI cap in 7-day steps; Insider default 7, retail 35; on Insider builds it is reset on *Check for updates*/*Resume*), `IsContinuousInnovationOptedIn` (`DW`; the "Get the latest updates as soon as they're available" toggle — UNVERIFIED name, widely reported), `AllowMUUpdateService` (`DW`; "Receive updates for other Microsoft products" toggle — UNVERIFIED), `RestartNotificationsAllowed2` (`DW`; "Notify me when a restart is required" — UNVERIFIED), `UxOption`, `LastToastAction`, `IsExpedited`, `FlightCommitted` (observed; internal).
* **The 35-day cap and "longer via registry".** The cap is UI-enforced. Setting `PauseUpdatesExpiryTime`/`*EndTime` directly to a far date is honoured by the client according to many reports (the Aetherinox "pause until 2051" tool relies on it), and Settings then displays that date. Reliability is UNVERIFIED and Microsoft may reset it (feature update, *Resume*, *Check for updates*, servicing changes). Microsoft's own statement of intent is that pause is a ≤35-day mechanism.
* **What happens at expiry.** The device scans, downloads and installs. On Windows 10 and current Windows 11 the *Pause* button is unavailable until that post-resume scan/install has happened ("your device will need to get the latest updates before it can be paused again" — ElevenForum tutorial text; Microsoft's consumer page says the device "will check for, download, and install the latest available updates"). So users cannot chain pauses without taking the current updates once — by design.
* **Home vs Pro:** identical UI on both. The policy that removes the pause UI (`SetDisablePauseUXAccess`) is Pro+.
* **OTW recommendation:** implement *Pause* by writing exactly the six `[UX]` values the UI writes (plus refresh of Settings), default cap 35 days, optional override to a configurable ceiling with warning; implement *Resume* by clearing them and triggering a scan. Prefer this over the WUfB policy pause on Home. Show the paused-until date on the dashboard, read from `PauseUpdatesExpiryTime` and `UpdatePolicy\Settings`.

### 5.3 Automatic Updates behaviour (`[POL\AU]`)

*Configure Automatic Updates* (`AutoUpdateCfg`) is one policy that writes several values:

| Value | Type | Meaning | Status |
| --- | --- | --- | --- |
| `NoAutoUpdate` | `DW` | 0 = AU enabled (policy Enabled), 1 = AU disabled (policy Disabled → "any updates available must be downloaded and installed manually" via Settings) | DOC. Also honoured when written directly ("registry keys used to configure group policies… policy overrides the preferences set by the local admin"). |
| `AUOptions` | `DW` | 2 notify for download & auto-install; 3 auto-download & notify for install; 4 auto-download & schedule install; 5 allow local admin to choose (**not available on Windows 10 or later**); 7 notify install & notify restart (**Server 2016+ only**); 1 = "keep my computer up to date disabled" (ancient) | DOC. On Windows 11 the practical choices are 2, 3, 4. |
| `ScheduledInstallDay` | `DW` | 0 every day, 1 Sunday … 7 Saturday | with `AUOptions`=4 |
| `ScheduledInstallTime` | `DW` | 0–23 | with `AUOptions`=4 |
| `ScheduledInstallEveryWeek`, `ScheduledInstallFirstWeek` … `ScheduledInstallFourthWeek` | `DW` | week-of-month scheduling | ADMX |
| `AutomaticMaintenanceEnabled` | `DW` | install during Automatic Maintenance instead of the scheduled time | ADMX |
| `AllowMUUpdateService` | `DW` | see §5.2 | ADMX |
| `NoAutoRebootWithLoggedOnUsers` | `DW` 1 | only with `AUOptions`=4; Microsoft warns it "was never created as a CSP… doesn't work exactly as per description… can result in no quality update reboots" and recommends deadlines instead | DOC |

### 5.6 Driver updates

* **Preferred:** `[POL] ExcludeWUDriversInQualityUpdate` `DW` 1 (Pro+ DOC; COMMUNITY says works on Home; UNVERIFIED). Reversible; side effect: WU-published driver/firmware updates (GPU, chipset, OEM firmware, Surface) stop arriving; the user must rely on OEM/vendor updaters. * **Device-installation search order:** `HKLM\SOFTWARE\Policies\Microsoft\Windows\DriverSearching\SearchOrderConfig` `DW` — 0 do not search Windows Update, 1 always search Windows Update, 2 search Windows Update only if no local driver (`DeviceSetup.admx`, *Specify search order for device driver source locations*, Pro+ DOC; the 0/1/2 mapping is ADMX-derived, COMMUNITY-confirmed). ### 5.8 Delivery Optimization (`HKLM\SOFTWARE\Policies\Microsoft\Windows\DeliveryOptimization`; MDM `./Device/Vendor/MSFT/Policy/Config/DeliveryOptimization/*`)

* **`DODownloadMode`** `DW`: 0 HTTP only (no peering; still uses DO cloud metadata; **the documented way to disable P2P**), 1 LAN (default; same public IP / subnet peering — Windows 11 default restricts LAN peers to the local subnet), 2 Group (AD site/domain SID/Entra tenant/`DOGroupID`), 3 Internet peers, 99 Simple (no DO cloud service at all — offline environments; DO auto-switches to it when the cloud is unreachable or files < 50 MB), **100 Bypass — deprecated starting in Windows 11: "Don't configure Download Mode to '100' (Bypass), which can cause some content to fail to download"** (falls back to BITS). Settings › Windows Update › Advanced options › Delivery Optimization ("Allow downloads from other devices" Off = mode 0 for consumers; the user setting is stored under the NETWORK SERVICE hive `HKU\S-1-5-20\SOFTWARE\Microsoft\Windows\CurrentVersion\DeliveryOptimization\Settings\DownloadMode` — UNVERIFIED path). Local machine reported `Get-DeliveryOptimizationPerfSnap` `DownloadMode = Internet` (3) with no policy set.
* **Bandwidth:** `DOPercentageMaxForegroundBandwidth`, `DOPercentageMaxBackgroundBandwidth` (0 = dynamic), `DOMaxForegroundDownloadBandwidth`, `DOMaxBackgroundDownloadBandwidth` (KB/s; recommended over % for low bandwidth), `DOSetHoursToLimitForegroundDownloadBandwidth`/`...BackgroundDownloadBandwidth` (business-hours schedule), `DOMinBackgroundQoS` (default 20 MB/s), `DOMonthlyUploadDataCap` (default 20 GB), `DOMinBatteryPercentageAllowedToUpload` (default: no upload on battery), `DOMinRAMAllowedToPeer` (4 GB), `DOMinDiskSizeAllowedToPeer` (32 GB), `DOMaxCacheAge` (3 days), `DOMaxCacheSize` (20 %), `DOAbsoluteMaxCacheSize`, `DOModifyCacheDrive`, `DOMinFileSizeToCache` (50 MB), `DOAllowVPNPeerCaching`, `DOVpnKeywords`, `DORestrictPeerSelectionBy` (1 subnet, 2 local DNS-SD), `DODelay*FromHttp`, `DOCacheHost*` (Connected Cache). Deprecated: `DOMaxDownloadBandwidth`, `DOPercentageMaxDownloadBandwidth`, `DOMaxUploadBandwidth` (2004). Settings UI exposes absolute/percentage download limits and the monthly upload cap; PowerShell: `Get-DeliveryOptimizationStatus`, `Get-DeliveryOptimizationPerfSnap`, `Delete-DeliveryOptimizationCache`. Edition: DO policies are Pro+ in the CSP; the Settings page is on Home too.
* **Trade-offs:** mode 0 saves upload bandwidth and reduces LAN chatter at the cost of slower/larger downloads on multi-PC LANs; 99 breaks nothing but disables MCC/peer benefits; 100 can break downloads (Store, WU) — refuse. Bandwidth caps that are too low (e.g. 5 % of a 10 Mbit link) make monthly CUs (~700 MB+ delta) take days and cause "download stuck" tickets — OTW should warn below a floor (suggest ≥ 1 MB/s absolute or ≥ 20 %).

### 5.11 Metered connection

* Windows Update does not auto-download over connections marked *metered* (except updates it classifies as priority/security — Microsoft: "some updates may still download"), unless `AllowAutoWindowsUpdateDownloadOverMeteredNetwork` is on. Wi-Fi/cellular can be marked metered per profile in Settings (`netsh wlan set profileparameter name="<SSID>" cost=Fixed|Variable|Unrestricted` for Wi-Fi). Ethernet has a Settings toggle too (Settings › Network & internet › Ethernet › *Metered connection*), which is the supported path.
* The registry hack `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\NetworkList\DefaultMediaCost` (`Ethernet`, `WiFi`, `Default`, `3G`, `4G` `DW` 1 unmetered / 2 metered — observed locally: `3G=2, 4G=2, Default=1, Ethernet=1, WiFi=1`) is owned by TrustedInstaller; scripts take ownership to flip `Ethernet=2`. Newer builds also store per-profile cost in `HKLM\SOFTWARE\Microsoft\DusmSvc\Profiles\{GUID}\*\UserCost` (`DW` 0/2, COMMUNITY). `Set-NetConnectionProfile` has **no** cost parameter (it sets Public/Private category); there is no supported public API to set Ethernet metered other than the Settings UI (COMMUNITY/UNVERIFIED: `Windows.Networking.Connectivity` is read-only for cost). Risks: (a) taking ownership of a TrustedInstaller key is a hardening anti-pattern and gets reverted by servicing, (b) metered mode also throttles Store, OneDrive, Outlook, Teams, background sync, Defender cloud lookups still work but definition downloads may defer, (c) it is *not* an update pause — security updates still come. **Recommendation:** OTW may *detect* and *display* metered state and deep-link to the Settings toggle; it must not edit `DefaultMediaCost`/`DusmSvc` ACLs.

Guardrail: expose `BlockMU` only in developer profile with a warning (unpatched runtimes are a real CVE surface).

### 5.13 Feature-update control and safeguard holds

* Two supported knobs: **defer** (`DeferFeatureUpdatesPeriodInDays` ≤365 — offer N days after Microsoft's release; combined with the annual cadence this effectively skips a year) and **pin** (`TargetReleaseVersion` = stay on `24H2` until its EOS). Consumer devices approaching EOS are force-migrated by Microsoft's rollout, and Windows 10 → 11 style product moves need `ProductVersion` too.
* **Safeguard holds** — Microsoft blocks the offer when telemetry shows a known compatibility issue for that hardware/driver/app; the *Windows release health* "known issues" list documents active holds; the hold clears automatically. `DisableWUfBSafeguards` (Pro+; resets after each feature update) bypasses them — Microsoft: for IT validation only. Consumers who *want* the update early should use the Installation Assistant/ISO knowingly, not a registry switch — OTW should show "held back by a safeguard hold" (safeguard-hold IDs are visible in WU-for-Business reports / Intune, and locally in `Get-WindowsUpdateLog` and the *Windows Update* Settings banner; a documented local registry indicator: **UNVERIFIED**) and link to release health rather than offering to bypass.
* Uninstall window for a feature update: `ConfigureFeatureUpdateUninstallPeriod` 2–60 days (default 10; Pro+; CSP) — a legitimate safety dial (raise to 30 in a "cautious" profile at the cost of disk).
* **EOS mapping** — §4.2. OTW should embed the table with the release-health page as source, refresh it, and warn at 90 days (configurable), 30 days, and at EOS; when the pinned `TargetReleaseVersionInfo` reaches EOS for the device's edition, offer to clear the pin (Microsoft will start offering the newer release anyway).

* **Detection recipe (all read-only):**
  1. MDM-managed: `HKLM\SOFTWARE\Microsoft\Enrollments\<GUID>` with `ProviderID = "MS DM Server"` (Intune) or another non-empty `ProviderID` and `EnrollmentType` in the MDM range — **note** an unmanaged machine still has dozens of `Enrollments` sub-keys with `EnrollmentType 1/2/10/11/18` and empty `ProviderID` (observed locally), so "key exists" is not a signal; also `dsregcmd /status` (`MdmUrl`, `AzureAdJoined`), and `HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\Update` having any values.
  2. Group-Policy-managed for updates: any value under `[POL]`/`[POL\AU]` **not written by OTW** (compare against OTW's own manifest), `UpdatePolicy\PolicyState\IsWUfBConfigured = 1`, `HKLM\SOFTWARE\Microsoft\WindowsUpdate\UpdatePolicy\GPCache` (`ActiveCache`, `CacheSet00x` — the *Refresh Group Policy Cache* task's mirror), and domain join (`Get-ComputerInfo CsPartOfDomain`).

  4. Settings shows "*Some settings are managed by your organization" and the *Configured update policies* page — OTW should render the same list (source = MDM/GP/registry) instead of hiding it.
  5. Result: if any of 1–3 → category is **read-only** with a "Managed by your organization (Intune / Group Policy / WSUS / Autopatch)" banner, an explanation, and only *view* + *export report* actions; never overwrite MDM/GP values (they revert on the next sync and generate compliance drift alerts for the admin — Autopatch raises "policy conflict" device alerts).

### 5.15 Remediation ("Repair Windows Update") — documented steps

1. **Windows Update Troubleshooter** — `msdt.exe /id WindowsUpdateDiagnostic` is dead on the way out (MSDT deprecated); Settings › System › Troubleshoot › Other troubleshooters › *Windows Update* now redirects to the **Get Help** app flows. `Get-TroubleshootingPack`/`Invoke-TroubleshootingPack` (TroubleshootingPack module) still exist on 24H2 but depend on the `.diagcab`/MSDT engine and should be treated as deprecated (UNVERIFIED removal date). OTW should deep-link `ms-settings:troubleshoot` / Get Help rather than embed MSDT.
2. **Reset Windows Update components (Microsoft, 2026-02 doc):** `net stop bits && net stop wuauserv && net stop cryptsvc` → delete `%ALLUSERSPROFILE%\Application Data\Microsoft\Network\Downloader\qmgr*.dat` → (only if the first pass fails) rename `%SystemRoot%\SoftwareDistribution\DataStore`, `\Download` and `%SystemRoot%\System32\catroot2` to `*.bak` → (only if still failing) `sc.exe sdset bits …` / `sc.exe sdset wuauserv …` to the default SDDL (Microsoft warns this overwrites existing ACLs) → the article still lists the long `regsvr32` list (atl, urlmon, mshtml, shdocvw, browseui, jscript, vbscript, scrrun, msxml/3/6, actxprxy, softpub, wintrust, dssenh, rsaenh, gpkcsp, sccbase, slbcsp, cryptdlg, oleaut32, ole32, shell32, initpki, wuapi, wuaueng, wuaueng1, wucltui, wups, wups2, wuweb, qmgr, qmgrprxy, wucltux, muweb, wuwebv — several of these no longer exist on Windows 11 and `regsvr32` will error harmlessly; the step is legacy advice retained in the doc) → `netsh winsock reset` → `net start bits && net start wuauserv && net start cryptsvc`. Microsoft's short form: `net stop wuauserv & rd /s /q %systemroot%\SoftwareDistribution & net start wuauserv`. Side effects: update history view is cleared (WUA `QueryHistory` still works from the datastore? — no: the datastore is the history; history is lost), hidden updates are un-hidden, DO cache unaffected, pending downloads restart. Requires admin; do it only when the user asks or a health check fails.
3. **Component store repair:** `DISM /Online /Cleanup-Image /RestoreHealth` (needs WU or a `/Source`; policy `[POL]`… `RepairContentServerSource` for WSUS-only shops), then `sfc /scannow`. Order: DISM first, then SFC.
4. **Repair reinstall from Settings (22H2+):** Settings › System › Recovery › *Fix problems using Windows Update* › **Reinstall now** — downloads a "repair version" of the current OS build via WU and reinstalls in place keeping apps/files/settings; not available on managed devices or when WU is broken; OTW should deep-link (`ms-settings:recovery`) and explain, not automate.
5. **Restore OTW-written settings:** the *Resume updates now* panic button = clear `[UX]` pause values, remove OTW-authored `[POL]`/`[POL\AU]` values (only those in OTW's manifest), then `UsoClient StartScan` / WUA `Search`, then `Update-MpSignature`, then show the dashboard.

## 7. Safety analysis and guardrails

### 7.1 Risk model for update controls

| Mechanism family | Security exposure | Reliability / drift | Reversibility | Verdict |
| --- | --- | --- | --- | --- |
| Settings-app pause ≤35 d (WU-001) | Bounded: ≤35 d without quality updates; Defender intelligence continues | UI-written values; Windows may reset on servicing; auto-resume + forced install at expiry | Trivial (clear values) | **Ship** (default control) |
| Registry pause > 35 d (WU-001 extended / WU-002) | Grows linearly with time; user forgets | Undocumented; may be reset; Insider builds reset it | Trivial | **Ship only behind explicit override + ceiling + reminders** |
| WUfB deferral (WU-005/006) | Feature: none; quality: ≤30 d | Documented, stable, effective from next scan | Trivial | **Ship** (Pro+; best-effort Home) |
| TargetReleaseVersion pin (WU-007) | None until EOS; **critical after EOS** (no security updates until Microsoft's forced migration) | Documented; overridden by Intune/Autopatch | Trivial | **Ship with EOS engine + warnings** |
| AUOptions 2/3/4 (WU-015) | Depends on user promptness (2/3); 4 = fine | Documented | Trivial | **Ship 3 and 4** |
| NoAutoUpdate/AUOptions=1 (WU-016) | Unbounded | Medic/Microsoft nag campaigns; users forget | Trivial technically | **Refuse** |
| Deadlines/notification (WU-020/023) | Improves patch compliance | Documented | Trivial | Ship in managed profiles |
| Driver exclusion (WU-010/033/035) | Loses firmware/driver security fixes; per-update hide is precise | Documented / WUA | Trivial | Ship WU-010 + WU-035; WU-033 advanced |
| DO mode 0/1/99 (WU-036) | None | Documented | Trivial | Ship |
| DO mode 100, DoNotConnect…, DisableWindowsUpdateAccess (WU-029/028) | Breaks Store/Defender/DO/WU | Documented as breaking | Trivial but damage already done | **Refuse** |
| Service/task/ACL hacks (WU-050/051/052), hosts/firewall (WU-053), DefaultMediaCost ownership (WU-046) | Unbounded; often also breaks Defender platform/Store | Reverted by CUs/Medic; leaves broken servicing stack; Defender flags hosts hijack | Not clean (ACLs, SDDL) | **Refuse; detect & repair** |
| Store/Edge/Office/.NET update disabling (WU-038/041/042/045) | App-level CVEs (browser!) | Documented policies | Trivial | Store: expose reluctantly; Edge 0: refuse; .NET BlockMU: developer profile only |
| Defender intelligence blocking (WU-043) | Immediate | — | — | **Never** |

Concrete "why" for the refuse-list (numbers from Microsoft docs): `DoNotConnectToWindowsUpdateInternetLocations` "may cause connection to public services such as the Microsoft Store, Windows Update client policies, and Delivery Optimization to stop working"; `DODownloadMode=100` "can cause some content to fail to download"; `RemoveWindowsUpdate_ICM` disables automatic updating entirely; `WaaSMedicSvc` is a PPL service whose purpose is to repair exactly the damage those tools do; disabling `wuauserv` breaks Store OS-component installs, Optional Features/FoD, language packs, Defender platform/engine updates (delivered via WU), .NET (MU) and the WUA API OTW itself uses; Edge Update docs say `AutoUpdateCheckPeriodMinutes=0` "isn't recommended, as it prevents Microsoft Edge Update itself from receiving stability and security updates".

### 7.2 Guardrails OTW should enforce (design requirements)

1. **Documented values only, documented locations only.** Every write goes to a `[POL]`/`[POL\AU]`/`[UX]`/DO/Store/Edge/MRT/.NET value listed in §6 with a Microsoft or ADMX source; no service `Start`, ACL, SDDL, task or hosts edits in the Windows Update category ever. Values are validated against ranges (`0–365`, `0–30`, `0–23`, whitelist for `TargetReleaseVersionInfo`, ISO date format for pause values, `2/3/4` for `AUOptions`).
2. **Pause cap = 35 days by default.** Extension beyond 35 d requires a modal acknowledging (a) no security updates during the pause, (b) Microsoft may reset it, (c) OTW will nag weekly; hard ceiling configurable (default 90 d); never write dates > 1 year; show a countdown; the app's background service re-checks and warns at 7/1 days before expiry and when a pause has been extended > 2 times.
3. **Never touch Defender intelligence.** No preset may block `Definition Updates`, remove `MicrosoftUpdateServer`/`MMPC` from the fallback order, disable `WinDefend`/`MpCmdRun` scheduled tasks or block Defender endpoints; *Resume/Repair* always runs `Update-MpSignature`; the dashboard shows signature age and turns red > 3 days.
4. **"Resume updates now" panic button** (also CLI `otw update resume --all`): clears all six `[UX]` pause values, deletes OTW-authored `[POL]`/`[POL\AU]`/DO values listed in the app's manifest (never foreign values), triggers `IUpdateSearcher.Search` (or `UsoClient StartScan`), then shows results. Idempotent; logged; requires confirmation only if a TargetReleaseVersion pin would be removed while a feature update is pending.
5. **Update-status dashboard** (read-only, always visible in the category): last successful scan/install (`IAutomaticUpdates2.Results`), pending updates (`Search("IsInstalled=0")`, count + top titles + severity), pending reboot, paused-until (per class), deferrals in effect, target release + **days to EOS for this edition** (green ≥180, amber <90, red <30/EOS), effective policy list with **source** (MDM / GP / OTW / other registry) — mirroring Settings' *Configured update policies* page, hidden updates list, DO mode + bandwidth caps, Defender signature age, WU service health (services' start types vs default, protected-task tampering), and "last 30 days history" (`QueryHistory`).
6. **EOS engine.** Embedded table (§4.2) + optional refresh from the Microsoft Graph Windows Updates API / release-health page; per-edition computation (Home/Pro vs Ent/Edu vs LTSC); warn at 90 d (configurable), 30 d, EOS; when the *current* version is EOS and no pin exists, recommend updating; when a pin targets an EOS version, offer one-click removal; refuse `26H1` and any string not in the whitelist.
7. **Managed-device detection → read-only** (§5.14): if Intune/MDM (`ProviderID = "MS DM Server"` or non-empty ProviderID with Update policies present), Group Policy (`IsWUfBConfigured=1`, foreign `[POL]` values, GPCache), WSUS (`WUServer` + `UseWUServer=1`, `ssManagedServer`), or ConfigMgr client is detected, the category shows "Managed by your organization" and only offers *View*, *Export report*, and *Open Settings*; the CLI returns a distinct exit code; the user may override only with a `--i-am-the-admin` style flag that logs a warning.
8. **Snapshot + revert + drift.** Before any write, capture the affected values (and `UpdatePolicy\Settings/PolicyState`) into the app's snapshot store; provide one-click revert per tweak and per session; drift detection re-reads after each cumulative update (build/UBR change) and reports values Windows reset (expected for `[UX]` pause and `DisableWUfBSafeguards`).
9. **Audit trail.** Every change → Windows Event Log (custom source) with before/after, user, and reason; every refusal (e.g. user requested a refuse-list item via CLI) → logged too.
10. **Home-edition honesty.** For every Pro+ policy applied on Home, mark the tweak "best-effort (undocumented on Home)", read back the effective state after the next scan (`PolicyState`, `IAutomaticUpdates.Settings`, `Search`) and show "Verified working / Not honoured" instead of assuming.
11. **No silent forced restarts from OTW itself.** OTW never triggers `RestartDevice`; it can *schedule* through the WU/USO surface the user already sees.
12. **Presets:** *Balanced* = active hours + `AllowOptionalContent`=3 (Pro+) / toggle off (Home) + DO mode 1 + no pause; *Privacy/Stability* = adds `ExcludeWUDriversInQualityUpdate`, MSRT opt-out, quality deferral ≤7 d, feature deferral 90–180 d or TRV pin (with EOS check), DO mode 0, Insider blocked; *Managed workstation* = deadlines 7/2 (QU) with NoAutoReboot, notification level 1 (active hours only), restart-notify on; *Kiosk* = maintenance windows (24H2+), notification level 2, `SetDisableUXWUAccess`. No preset writes `NoAutoUpdate=1`, `AUOptions=1`, `DODownloadMode=100`, or any refuse-list item.

### 7.3 Things OTW must explicitly refuse to do (and instead detect/repair)

* Disable, delete, re-ACL, or set `Start=4` on `WaaSMedicSvc`, `wuauserv`, `UsoSvc`, `DoSvc`, `BITS`, `TrustedInstaller`, `cryptsvc`; zero their `FailureActions`.
* Disable, delete, or re-ACL scheduled tasks under `\Microsoft\Windows\UpdateOrchestrator`, `\WindowsUpdate`, `\WaaSMedic`, `\InstallService`.
* Write `NoAutoUpdate=1`, `AUOptions=1`, `DisableWindowsUpdateAccess=1`, `DoNotConnectToWindowsUpdateInternetLocations=1` (unless WSUS present — then read-only anyway), `DODownloadMode=100`, `RemoveWindowsStore=1`, Edge `UpdateDefault=0`/`Update{…}=0`/`AutoUpdateCheckPeriodMinutes=0`, any Defender signature blocking, hosts/firewall blocks of update endpoints, `DefaultMediaCost`/`DusmSvc` ownership changes, decade-long pause dates, `DisableWUfBSafeguards` outside an explicit IT-validation mode, `TargetReleaseVersion` to an EOS or non-upgrade (26H1) release.
* Silently write Pro-only policies on Home and claim success.
* Fight MDM/GP: overwrite `PolicyManager` values or values that Group Policy re-applies (they revert and generate admin alerts).
