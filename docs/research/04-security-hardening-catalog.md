## 1. Executive summary

* **Baselines current on 2026-08-16:** Microsoft Security Baseline for **Windows 11 25H2** (Security Compliance Toolkit package released 2025-09-30, minor delta from the **24H2** baseline of 2024-10-01); **DISA Microsoft Windows 11 STIG V2R8** (released 2026-07-01 — 256 rules: 27 CAT I, 213 CAT II, 16 CAT III; STIG SCAP Benchmark V2R8 published 2026-07-16); **CIS Microsoft Windows 11 Enterprise Benchmark v5.1.0** (v5.0.0 in April 2026, v5.0.1 hotfix, then v5.1.0 listed on cisecurity.org), **CIS Windows 11 Stand-alone v5.0.0** (April 2026), **CIS Microsoft Intune for Windows 11 v5.0.0** (2026-06-25); **ACSC "Hardening Microsoft Windows 11 workstations"** (living guide, cyber.gov.au); **HardeningKitty** finding lists (223 machine items in `finding_list_0x6d69636b_machine.csv`, MIT).
* **The Windows 11 24H2/25H2 platform already ships much of "Basic":** SMB signing required by default on all editions (24H2), NTLMv1 removed (24H2), TLS 1.0/1.1 disabled by default in SCHANNEL (24H2), LSA protection auto-enabled after a compatibility audit (24H2 upgrade path; default on new enterprise-joined 22H2+ installs), Credential Guard default-on for licensed (Enterprise/Education) domain/Entra-joined 22H2+ devices, HVCI/memory integrity on by default on new installs with capable hardware, PowerShell 2.0 removed (25H2; removed from 24H2 by 2025 servicing), WMIC uninstalled (25H2), Remote Mailslots disabled (24H2), Point-and-Print driver installs admin-only (since Aug 2021), Print Spooler RPC packet privacy enforced. **The app's first job for these items is therefore to *verify and report drift*, not to "turn on" things that are already on.**
* **Highest-value / lowest-breakage items (Basic & Balanced):** the 15 listed in §3.4 — firewall on all profiles with inbound-block + logging; SmartScreen (Explorer) = Block; Defender cloud protection High + Block-at-first-sight + PUA block; the ~13 low-noise ASR rules; LSA PPL; HVCI/Core-isolation confirmation; LLMNR off; insecure guest auth off; AutoRun/AutoPlay off; NTLMv2-only + no LM hash + anonymous restrictions; UAC secure desktop/consent; script-block + module logging + command-line auditing; event log sizes; WDigest = 0; AlwaysInstallElevated = 0; disable Solicited Remote Assistance; SMBv1 absent; sudo disabled.
* **Highest-breakage items (gate behind Strict/Paranoid, with explicit warnings and audit-first modes):** NTLM restrict/deny (`RestrictSendingNTLMTraffic=2` / `RestrictReceivingNTLMTraffic=2`), SMB client NTLM blocking and SMB encryption mandate, SMB signing/dialect minimums on Home NAS estates, Controlled Folder Access in block mode, ASR "Block process creations from PSExec/WMI", "Block executables unless prevalence/age/trusted" and "Block persistence through WMI" (SCCM/RMM breakage), disabling Print Spooler, disabling NetBIOS/mDNS (breaks discovery of some NAS/printers/casting devices), disabling Windows Script Host (breaks VBS/JS logon scripts and some installers), disabling TLS 1.0/1.1 on 23H2 (old LOB apps), FIPS mode, Kernel-mode HW stack protection/HVCI/Credential Guard with UEFI lock on machines with incompatible drivers or NTLMv1/CredSSP/MS-CHAPv2 dependencies, `DisableDomainCreds=1`, PKU2U off on Entra-joined peers, DoH "Require" mode, mandatory ASLR system-wide, `ValidateAdminCodeSignatures=1`, removable-storage deny.
* **Levels (§3):** *Basic* = "verify what Windows already does + zero-breakage defaults"; *Balanced* = MS Security Baseline (minus domain-only items) ≈ CIS Level 1 (Stand-alone profile) ≈ STIG CAT I + low-impact CAT II, with Defender advanced features in audit; *Strict* = full STIG (all CATs applicable to a standalone workstation) + CIS Level 2 + ACSC "should" items, Defender features in block; *Paranoid* = CIS L2 + BitLocker + NG profiles, NTLM/legacy protocol removal, application allow-listing (WDAC/Smart App Control), UEFI locks, device-class blocking, DoH-required, LOLBin outbound blocks — labelled "may break things; test first; snapshot mandatory".
* **Audit/compliance mode (§6):** a read-only scan that evaluates each catalogue item's *actual* state (registry/secedit/auditpol/WMI/MpPreference/netsh) against a selected reference (MS 25H2, STIG V2R8, CIS L1/L2 references, OTW levels), produces per-item Pass/Fail/N/A/Manual with severity weights (STIG CAT I=10 / II=3 / III=1), a weighted score, and machine-readable output (JSON/CSV/SARIF/CKL-like) — never changing anything, and never bundling licensed CIS text or Microsoft LGPO/Policy Analyzer binaries.

## 3. OTW hardening levels — security definitions

### 3.1 Design principles

1. **Verify-first:** an item that Windows 24H2/25H2 already enforces by default (SMB signing, TLS 1.0/1.1 off, NTLMv1 gone, LSA PPL, HVCI, PS2 removed) is a *drift check* at Basic and a *remediation* only when drifted; the app never "fights" the OS.
2. **Audit before block** for every Defender/ASR/CFA/network-protection control and for NTLM/SMB restrictions: Balanced applies audit modes where they exist, Strict flips to block; the UI shows event-log evidence (Defender Operational 1121/1122, NTLM Operational, SMB client/server audit events) collected between the two steps.
3. **Edition/version gating:** every item carries `appliesTo` (Home/Pro/Enterprise/Education; min build) and `managedBy` (GPO/MDM path) so the app can show "managed by your organization" and refuse to override MDM/GPO-set values.
4. **Reversibility:** every applied change is snapshotted (registry values incl. absence, secedit INF export, `auditpol /backup`, `Get-MpPreference` dump, firewall profile export, feature state) — the Strict/Paranoid tiers require a restore point + snapshot before apply.
5. **No self-inflicted lock-out:** UEFI-locked settings (`RunAsPPL=1`, `LsaCfgFlags=1`, HVCI `Locked=1`) and BitLocker protector changes are *Paranoid* only, with an explicit "you will need firmware access to undo this" consent.

### 3.3 Placement rules (how an item gets a level)

* Item is on-by-default in supported Windows 11 releases and in the MS baseline → **Basic** (drift check + repair).
* Item is in the MS baseline *and* the app knows no common breakage on standalone → **Balanced**.
* Item is in the MS baseline but breaks a common home/SMB scenario (guest NAS, USB portable apps, printer discovery) → **Balanced with a scenario toggle** (e.g., "I use a NAS without passwords" → keep insecure guest auth *audit* only, warn), never silently.
* Item is only in STIG/CIS L2/ACSC and/or has an audit mode → **Strict** (audit at Balanced when possible).
* Item removes a protocol/feature with no fallback, adds UEFI locks, or requires organisational infrastructure (WDAC, LAPS directory, Kerberos) → **Paranoid** or **Enterprise-only** flag.
* Domain-only items (Kerberos armoring, hardened UNC paths, secure channel, dMSA, PKINIT hash agility, LAPS AD/Entra backing) are placed at Balanced/Strict but marked `scope: domain` and skipped (N/A) on standalone machines.

### 3.4 Top-15 highest-value / lowest-breakage (Basic/Balanced defaults)

1. Windows Firewall on for Domain/Private/Public, default inbound Block, logging (dropped + successful, 16 384 KB), no local-rule merge on Public.
2. Defender: real-time + cloud (MAPS Advanced) + Block-at-first-sight + cloud block level **High** + extended cloud timeout 50 s + PUA **Block** + Tamper Protection verified on.
3. Standard ASR set in Block: LSASS credential theft (`9e6c4e1f`), vulnerable signed drivers (`56a863a9`), Office child processes (`d4f940ab`), Office executable content (`3b576869`), Office injection (`75668c1f`), Win32 API from macros (`92e97fa1`), executable content from email (`be9ba2d9`), JS/VBS launching downloaded executables (`d3e037e1`), obfuscated scripts (`5beb7efe`), Adobe Reader child (`7674ba52`), Outlook child (`26190899`), impersonated system tools (`c0033c00`), Safe Mode reboot (`33ddedf1`).
4. SmartScreen for Explorer = Block (`EnableSmartScreen=1`, `ShellSmartScreenLevel=Block`) + Edge SmartScreen + PUA download blocking.
5. LSA protection (`RunAsPPL=2` without UEFI lock) + confirm HVCI/memory integrity running + vulnerable-driver blocklist on.

### 3.5 Top-10 high-breakage items (Strict/Paranoid, warn + audit-first)

1. NTLM: `RestrictSendingNTLMTraffic=2` / `RestrictReceivingNTLMTraffic=2` (deny) and SMB client `BlockNTLM` — breaks workgroup shares, NAS, local-account RDP/WinRM/Admin$, IP-address connections, many VPN/proxy auths.
2. SMB client `RequireEncryption=1` / min dialect 3.1.1 on Home NAS estates (older NAS, scan-to-SMB printers, media players).
3. Controlled Folder Access = Block (game saves, backup/sync agents, Office add-ins, dev tools writing to Documents).
4. ASR: *Block process creations from PSExec/WMI* (SCCM/RMM), *Block executable files unless prevalence/age/trusted list* (LOB/dev builds), *Block persistence through WMI* (SCCM/monitoring agents), *Block Office apps injecting* (BeyondTrust/Heimdal), *Block untrusted/unsigned processes from USB* (portable apps).
5. Disabling Print Spooler / Windows Script Host / Secondary Logon / NetBIOS+mDNS everywhere (printing, logon scripts & installers, `runas`, discovery of NAS/printers/casting devices).
6. TLS 1.0/1.1 explicit disable + strict cipher-suite order on 23H2 (old LOB apps, legacy management consoles), FIPS mode (`FipsAlgorithmPolicy\Enabled=1`), Kerberos AES-only.
7. Credential Guard / HVCI / Kernel-mode HW stack protection with UEFI lock on machines with third-party LSA plug-ins, NTLMv1/CredSSP/MS-CHAPv2 VPN, unsigned/anti-cheat drivers (BSOD risk; firmware access needed to undo).
8. `DisableDomainCreds=1` (Credential Manager unusable — mapped drives/RDP saved creds), PKU2U `AllowOnlineID=0` on Entra-joined peer scenarios, `DontDisplayNetworkSelectionUI=1`, `ScRemoveOption` force-logoff.
9. DoH *Require* (`DoHPolicy=3`) — resolution fails on networks whose resolvers lack DoH/are not in the known list; captive portals; AD DNS.
10. Mandatory ASLR system-wide (`ForceRelocateImages`), `ValidateAdminCodeSignatures=1`, removable storage `Deny_All`, device-class blocking (Thunderbolt/1394), Smart App Control / WDAC enforce, LOLBin outbound blocks — legitimate unsigned admin/dev tools stop working.

## 4. Hardening catalogue

**Conventions used in the tables**

* **Mechanism** — exact registry path / value / type / data, or the PowerShell cmdlet, `secedit` INF key, `auditpol` subcategory, `netsh` command, service name, or optional-feature name. `HKLM\…\Policies\…` paths are the *policy* location (what GPO/MDM writes and what the app should write to be baseline-comparable); where a non-policy "preference" location also exists it is noted.
* **Applies** — H = Home, P = Pro, E = Enterprise, Ed = Education; version notes (e.g., "24H2+ default"). "domain" = only meaningful when domain/Entra-joined.
* **Baselines** — **MS** = Microsoft Security Baseline 25H2 (Y = configured; "def" = Windows default, not in GPO); **STIG** = Windows 11 STIG V2R8 rule ID (with CAT if I or III; otherwise CAT II); **CIS** = CIS Windows 11 profile L1/L2/BL/NG with approximate section (verify against licensed v5.x); **ACSC** = in the ACSC Windows 11 hardening guide; **HK** = HardeningKitty machine list ID.
* **Level** — B = Basic, Bal = Balanced, S = Strict, P = Paranoid; "chk" = read-only check/report only; "(A)" = audit mode at that level; "dom" = domain-scope only; "ent" = requires Enterprise/Education or infrastructure.
* **Src** — short keys resolved in §8.

### 4.H Microsoft Defender Antivirus — engine, cloud, PUA, network protection, controlled folder access

**Preconditions the app must check first:** (1) Defender AV must be the *active* AV (`Get-MpComputerStatus`.`AMRunningMode` = "Normal"; if a third-party AV is registered, Defender is in *passive/disabled* mode and ASR/CFA/NP/cloud settings have **no effect** — MDE onboarding excepted). ## 6. Proposal — read-only audit / compliance mode

**Goal:** score the machine against (a) OTW levels, (b) Microsoft Security Baseline 25H2/24H2 (Computer+User+Defender AV, optionally BitLocker/Credential Guard GPOs), (c) DISA STIG V2R8, and (d) CIS L1/L2/BL/NG *references* — without changing anything and without shipping licensed text.

1. **Rule model.** Each catalogue item is a `Rule` with: `id`, `title`, `domain`, `checks[]` (each check = provider + locator + expected + comparator; providers: `Registry`, `RegistryPolicyPreference` (checks policy path first then preference), `Secedit` (`[System Access]/[Privilege Rights]/[Registry Values]`), `AuditPol` (subcategory GUID), `MpPreference`/`MpComputerStatus`, `Wmi` (`Win32_DeviceGuard`, `Win32_EncryptableVolume`, `Win32_Tpm`, `Win32_OptionalFeature`), `WindowsFeature`/`Capability`, `Service`, `Firewall` (`NetFirewallProfile/Rule`), `Netsh` (portproxy, teredo, dns encryption), `Bcdedit`, `File`/`Acl`, `EventLogQuery` (e.g., "no 3065/3066 in 30 days"), `Cmd` (`dsregcmd`, `reagentc`, `citool`) — every provider is read-only in audit mode), `appliesTo` (editions, min/max build, domain-joined, HW capability predicate), `mappings[]` (`{framework: MS-25H2|MS-24H2|STIG-V2R8|CIS-W11E-5.1.0|CIS-W11S-5.0.0|ACSC|OTW, ref: id, severity/profile}`), `breakageNotes`, `level`, `remediation` (used only in apply mode).
2. **Result states.** `Pass`, `Fail`, `NotApplicable` (edition/HW/domain predicate false — e.g., Credential Guard on Home), `Manual` (organisational STIG rules such as WN11-00-000240), `Error` (provider failure — reported, not scored), `ManagedByPolicy` (value set by GPO/MDM — still scored, flagged as locked). Store the *observed value* alongside expected for every check.
3. **Scoring.** Per framework: STIG uses CAT weights (I=10, II=3, III=1) → `score = Σ pass-weight / Σ applicable-weight`; MS baseline: unweighted % of applicable settings (optionally split "security-critical" vs "hygiene" using OTW level as weight: Basic 3, Balanced 2, Strict 1, Paranoid 0.5); CIS: % per profile (L1, L2, BL, NG); OTW: per level pass % + a "Top-15" pass count. Show counts, not just percentages; never claim "CIS certified" (only CIS-CAT can).
4. **Evidence & drift.** Persist each run (JSON) with timestamp, build/UBR, hash of the rule set; diff runs to show *drift* (what changed since last audit — including changes made by Windows updates or by MDM), and correlate with the OTW change journal to separate "we changed it" from "something else changed it".
5. **Outputs.** GUI dashboard (score per framework, domain heatmap, failing CAT I list first, evidence panel per rule with "why it matters / what breaks if fixed" text); CLI `otw audit --framework stig-v2r8 --format json|csv|sarif|html --exit-code` (exit code = number of CAT I fails, capped) for CI/RMM; STIG **CKL/CKLB-style checklist export** (rule ID, status, finding details, comments) for eMASS/STIG Viewer import — the format is public; MS baseline comparison export similar to Policy Analyzer's CSV; CIS export lists recommendation IDs and pass/fail only.
6. **Safety.** Audit runs read-only providers exclusively (no `secedit /configure`, no `Set-*`); requires admin only for reading protected locations (Security log, some Defender values); rate-limits WMI; timeouts per provider; excludes any Internet lookups except optional "check MS SCT version" metadata.
7. **Extensibility.** Rule packs are YAML/JSON signed and versioned (`ms-baseline-25h2.yaml`, `stig-v2r8.yaml`, `otw-levels.yaml`, `cis-refs.yaml` containing only IDs/expected values); community can PR new packs; the STIG pack can be regenerated from the public XCCDF/SCAP benchmark (parse `<Rule id> <ident> <check-content>` registry references) to track quarterly releases; the MS pack from SCT PolicyRules/`registry.pol` (PReg format is documented — implement the parser, do not bundle LGPO).

## 7. Implementation notes for the hardening engine

* **Write to policy paths** (`HKLM\SOFTWARE\Policies\…`, `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\…`) so states are baseline-comparable and survive user toggles; but detect and respect existing GPO/MDM control: if `HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\…` (MDM) or `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Group Policy\History` shows the setting is managed, show "managed by your organization" and do not override. On domain-joined machines GPO refresh will revert local policy-path writes anyway (only `HKLM\SOFTWARE\Policies` under GPO scope) — warn.
* **secedit on Home:** `secedit /export|/configure` works on all editions (secpol.msc UI is what's missing). Always export first (`secedit /export /cfg backup.inf /areas SECURITYPOLICY USER_RIGHTS`) and keep it as the rollback artefact; apply with a minimal INF containing only the changed keys and `[Version] signature="$CHICAGO$" Revision=1`.
* **auditpol** changes are overwritten by GPO/MDM audit CSP; back up with `auditpol /backup /file:` and restore with `/restore`.
* **Defender:** prefer `Set-MpPreference`/`Add-MpPreference` (via `Microsoft.Management.Infrastructure` `MSFT_MpPreference` from C# rather than spawning PowerShell); if the machine is MDE/Intune-managed or Tamper Protection blocks the setting, surface it instead of failing silently (`Set-MpPreference` may return success while TP ignores it — verify by re-reading). Policy registry (`HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\…`) overrides preferences — write policy for baseline items, preferences for user-scoped toggles.
* **Reboot/logoff requirements:** LSA PPL, VBS/HVCI/CG, KM stack protection, SEHOP, DEP policy, `LmCompatibilityLevel` (effective immediately for new sessions), SMB service settings (`Restart-Service LanmanServer/LanmanWorkstation` or reboot), Dnscache restart for mDNS/LLMNR, Explorer restart for AutoPlay/attachment policies, `gpupdate /force` not required for local registry writes but many settings are read at logon (UAC, lock-screen). Track `RebootRequired` per item; batch.
* **Order of operations:** snapshot → apply registry/secedit/auditpol → apply Defender preferences → apply firewall → apply features/services (last; longest) → verify each → write change journal (Windows Event Log `Open The Windows/Operational` + JSON) → reboot prompt.
* **Rollback:** per item inverse (restore prior value or delete if absent), plus whole-run restore point (`Checkpoint-Computer` requires System Protection on — check first) and secedit/auditpol/firewall exports.
* **Edition/build detection:** `EditionID` (`Core`, `CoreSingleLanguage` = Home; `Professional`, `ProfessionalWorkstation`, `Enterprise`, `EnterpriseS`(LTSC), `Education`, `ProfessionalEducation`), `DisplayVersion` (23H2/24H2/25H2), `CurrentBuild` (22631/26100/26200), `UBR`; licence for Credential Guard via `EditionID` ∈ {Enterprise, Education, EnterpriseS} (Pro = "not licensed" → check only). Windows 11 LTSC 2024 (build 26100) counts as 24H2 for feature purposes.
* **Conflict detectors** (drive level gating and warnings): ConfigMgr client (`CcmExec`), third-party AV (SecurityCenter2), BeyondTrust/Heimdal (I11), Xbox app usage (Teredo), NAS guest shares (recent 4625/SMB client 31010 events? — SMB client audit `AuditInsecureGuestLogon` events 31017), printers installed (Spooler), RDP sessions in last 30 days (event 4624 logon type 10), PsExec/WMI process creations (4688 with `PSEXESVC`/`WmiPrvSE` parent), WSH script executions (4688 `wscript.exe`/`cscript.exe`), Office presence and add-ins, VPN clients (MS-CHAPv2/CredSSP), domain/Entra join state.
* **Licensing/attribution:** STIG (public domain) — cite rule IDs; MS baseline settings — cite; CIS — IDs only, link to cisecurity.org; HardeningKitty (MIT) — attribution if check logic is derived; Sysinternals Sysmon — user-initiated download, EULA acceptance; ACSC — Crown copyright/CC BY 4.0 (check licence page) — cite.
