# 02 — Competitive Landscape, Prior Art & Enterprise-Grade Requirements

**Project:** Open The Windows (OTW) — open-source, enterprise-grade Windows 11 privacy / hardening / debloat / tweak desktop app (C#/.NET, GUI + CLI)
**Research date:** 2026-08-16 (all "as of" statements refer to this date)
**Status:** Research report — informs product requirements, catalogue design and licensing decisions

> How to read this document: Section 1 is the executive summary. Sections 2–4 inventory the tools and score them in a feature matrix. Section 5 is a catalogue of *what actually breaks Windows* when these tools are used carelessly (the single most valuable input into OTW's risk model). Section 6 compares how each tool models "levels" and proposes OTW's model. Section 7 describes the "official" Microsoft way (GPO / Intune / baselines) that an enterprise-grade tool must respect. Section 8 is the enterprise-grade must-have checklist. Section 9 lists UX patterns worth copying, Section 10 covers legal/licensing constraints, Section 11 lists sources.

## 1. Executive summary

* The market splits into four families: **(a) privacy-toggle GUIs** (O&O ShutUp10++, W10Privacy, WPD, Spybot Anti-Beacon, Blackbird), **(b) debloat/tweak scripts and script-front-ends** (Win11Debloat, winutil, Sophia Script, privacy.sexy, WinScript, the abandoned Sycnex/W4RH4WK scripts, Andrew Taylor's Intune script), **(c) all-in-one GUI tweakers** (Winaero Tweaker, Wintoys, Optimizer, Winhance, builtbybel's FluentTweaker/BloatyNosy lineage, TidyOS, Talon), and **(d) hardening/compliance tooling** (HardeningKitty, Microsoft Security Compliance Toolkit + LGPO + Policy Analyzer, HotCakeX Harden System Security, PowerSTIG). Modified-OS projects (Atlas OS, ReviOS, tiny11) are a fifth, cautionary, family.
* **Nobody in families (a)–(c) is enterprise-grade.** None of them combine *all* of: dry-run, per-tweak snapshot + revert, drift detection/re-enforcement, Event Log audit trail, MDM/GPO awareness, machine-readable CLI output, signed/verifiable profiles, and a catalogue with per-build applicability metadata. The closest approximations are HotCakeX Harden System Security (presets + intents, verify mode, CLI with exit codes, Intune-detection, MSIX-signed, MIT) and a tiny (4-star) PowerShell project, SysAdminDoc/Debloat-Win11, whose *design* (policy catalogue with risk/scope/rollback metadata, JSON manifest + generated undo script, drift detect/remediate scripts with JSON/CSV output, Intune detection contract, presets per role) is almost exactly the shape OTW should take. Among the popular OSS scripts, Win11Debloat is the most mature engineering-wise (declarative feature JSON with paired `.reg` undo files and per-feature build ranges, `-WhatIf`, registry snapshot backup, real `reg load` of other users'/Default hives, `-Silent`/`-Config`, restore-point de-dupe), winutil has the best tweak *data model* (`OriginalValue`/`UndoScript`) but a history of service/WU breakage, Sophia has the best pre-flight guards, HardeningKitty has the best *audit* model, and Andrew Taylor's Intune script is the only one that is Authenticode-signed. privacy.sexy — the best *catalogue* design — is AGPL and effectively unmaintained since 2025-04. O&O even sells the missing piece — "ShutUp10 Premium continuously monitors your selected settings and automatically restores them, even after Windows updates" — as a paid upgrade, which is direct evidence that drift-monitoring is a differentiator.
* **The most common real-world breakages** are: (1) removing/blocking Edge or WebView2 and breaking Widgets/Outlook/Teams/Office sign-in; (2) disabling services (wlidsvc, TextInputManagementService, WSearch, LicenseManager, DoSvc/BITS/UsoSvc, Spooler, CDPSvc, XblAuthManager) that silently break Store, Start-menu typing, MSA/Xbox sign-in, Windows Hello, printing or updates; (3) hosts-file telemetry blocking that Defender flags as `SettingsModifier:Win32/HostsFileHijack` and that breaks NCSI/Store/Defender cloud; (4) Windows-Update-killing hacks (WaaSMedicSvc ACL/ownership changes, TargetReleaseVersion pinning, service disable) that leave machines unpatched or unable to be serviced; (5) removals that Windows silently reverts (Outlook (new), Copilot, Teams, Widgets return after feature/enablement updates; DevHome/Outlook are re-provisioned by Update), producing "the tool didn't work" tickets — plus OneDrive removal with Known-Folder-Move still active making Desktop/Documents "disappear".
* **Level model recommendation:** decouple three orthogonal axes — (i) a **per-category level dial** `Off / Basic / Balanced / Strict / Paranoid`, (ii) a **per-tweak risk badge** `Safe / Caution / Advanced / Breaking` (with an "irreversible" flag), and (iii) **named profiles** (`Home`, `Power User`, `Enterprise Workstation`, `Developer`, `Gamer`, `Kiosk/Shared`, `Privacy-Max/Air-gapped`, plus custom) that are just saved dial positions + per-tweak overrides. Every tweak carries `appliesTo` (build/edition/arch ranges), `verifiedOn` evidence, `managedBy` policy mapping, and revert data.
* **Licensing constraints that matter:** privacy.sexy's collections are **AGPL-3.0** — do not copy YAML into an MIT/Apache app; CIS Benchmark *text* is CC BY-NC-SA 4.0 with commercial-embedding requiring a paid SecureSuite Product Vendor membership — reference recommendation IDs, do not ship the prose; DoD STIGs are US-Government works (17 U.S.C. §105, public domain in the US) — safe to implement and reference; Microsoft baselines/RTLFB content is freely downloadable but LGPO.exe/Policy Analyzer binaries are under Microsoft Software License Terms — do not bundle them, re-implement the documented `registry.pol` ("PReg") format instead; Win11Debloat, winutil, Sophia, HardeningKitty, Harden-Windows-Security, RemoveWindowsAI, PowerStig, Sycnex are MIT; Optimizer, WinScript, simplewall, Portmaster **and Andrew S Taylor's De-Bloat repo** are GPL-3.0; W4RH4WK is Beer-ware (not MIT); Winhance is PolyForm Shield 1.0.0 (source-available, no competing redistribution); tiny11builder has no licence file; Talon is BSD-3 in-repo but sold under a contradictory commercial licence; ShutUp10/W10Privacy/Wintoys/Blackbird/Anti-Beacon/WPD/Winaero are proprietary freeware. Microsoft explicitly refused permission to redistribute LGPO.exe ("No. Please link back to this site").

| **Talon / TidyOS / Atlas / ReviOS** | One-click / playbook with a few Y/N choices (e.g., ReviOS "Disable Defender: default Disable") | almost none | Cautionary: no dial, no per-item consent, security-relevant defaults hidden. |

### 6.2 Recommendation for Open The Windows

Model three **orthogonal** axes; never collapse them into one colour.

1. **Per-category level dial** — `Off · Basic · Balanced · Strict · Paranoid` for each category (Telemetry & diagnostics, Advertising & suggestions, Cloud & account sync, AI features (Copilot/Recall/Click-to-Do), Search & Bing, Apps & bloat, Edge, OneDrive, Services, Scheduled tasks, Windows Update, Security hardening, Network & firewall, UI/UX, Performance & power, Developer conveniences).
   * *Basic* = zero functional loss (Microsoft-supported switches only, e.g., AllowTelemetry=Required, ads off, advertising ID off).
   * *Balanced* = default for most people; ≈ ShutUp10 "Recommended" + Win11Debloat defaults + MS security baseline; small, well-understood functional trade-offs.
   * *Strict* = ≈ ShutUp10 "Limited" + privacy.sexy "Strict" + CIS L2-ish; visible functional loss (no Store suggestions, no MSA-dependent goodies, no widgets/Copilot).
   * *Paranoid* = RTLFB-class; expect breakage; only for air-gapped/kiosk/lab; requires acknowledgement.
   * The dial *selects* tweaks by their `level` metadata; users can then override individual tweaks.
2. **Per-tweak risk badge** — `Safe · Caution · Advanced · Breaking`, plus flags `irreversible`, `restart` (none/explorer/sign-out/reboot), `editionScope`, `managedByPolicy`, `verifiedOn`.
   * `Safe`: no known functional loss, fully reversible. `Caution`: loses a feature some people use (Xbox, Widgets, Phone Link); reversible. `Advanced`: can break workflows (Store sign-in, printing, search, WU deferrals), needs expertise; reversible but not trivially. `Breaking`: known to break Windows components / security / servicing (Edge/WebView2 removal, WU disable, Defender off, hosts telemetry blocking, ACL/ownership changes) — never selected by any dial position, requires `--allow-breaking`, shows the B-catalogue entry (§5).
   * Mirrors winutil's "Advanced/Caution" labels and ShutUp10's third tier, but decoupled from *level*: a `Strict`-level tweak can be `Safe` (e.g., disable Spotlight), and a `Basic`-level tweak can be `Caution` on some editions.
3. **Named profiles** — a profile is just a saved set of dial positions + per-tweak overrides + scope + options, stored as signed JSON:
   * `Home` (Basic/Balanced, keeps Store/Xbox/MSA), `Power User` (Balanced/Strict, no AI, no ads, dev-friendly), `Enterprise Workstation` (Balanced privacy + MS baseline security + WU policy-only + "respect managed"), `Developer` (Power User + Dev Mode/WSL/Sandbox conveniences, keeps WebView2/Edge for tooling), `Gamer` (Balanced privacy, keeps Xbox/Game Bar/GPU scheduling, perf plan), `Kiosk / Shared` (Strict + lock-downs, per-machine, all users), `Privacy-Max / Air-gapped` (Paranoid, explicit acceptance), plus `Custom…` (start from any, save-as, share, sign).
   * HSS's *intents* and SysAdminDoc's role presets validate this; add per-profile *"what you lose"* summary generated from the selected tweaks' badges.

Supporting rules: (a) built-in profiles never include `Breaking`; (b) a dial move shows a diff before applying; (c) profiles pin a catalogue version and are re-validated when the catalogue or the OS build changes; (d) `scan` reports drift *against the profile*, not against Windows defaults; (e) "Reset to Windows defaults" is a separate action that uses captured pre-state first and documented Microsoft defaults second.

## 7. The "official way": Group Policy, Intune/MDM CSPs, Microsoft baselines, RTLFB — what an enterprise-grade tool must respect

An enterprise admin's mental model is: *settings are owned by a management channel* (GPO from AD, MDM/Intune CSPs, ConfigMgr baselines, or a local admin). A tweak tool that silently writes the same registry values is, at best, redundant and at worst a source of "why does this setting keep flipping?" tickets. OTW must therefore (a) know how each tweak maps to the official policy, (b) detect when the machine is managed and *not fight the channel*, and (c) be able to *emit* the official artifacts (GPO backup / registry.pol / Intune settings-catalog JSON / OMA-URI list) instead of applying locally.

### 7.1 Where policy lives and how to detect "managed"

| Signal | How to read it | Notes |
|---|---|---|
| Group Policy (domain or local) registry-based settings | `HKLM\SOFTWARE\Policies\...`, `HKCU\SOFTWARE\Policies\...`, `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\...` | Presence of a policy value in these hives is what the Settings UI uses to show "Some of these settings are managed by your organization". A local admin (or any tweak tool) can also write these keys — so *policy present* ≠ *managed by an org*. Distinguish by checking whether the value is delivered by a GPO (parse `%windir%\System32\GroupPolicy\Machine\Registry.pol`, or RSOP via `gpresult /x`) or by MDM (below). |
| MDM / Intune-delivered policy | `HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\<Area>\<Policy>` and `...\PolicyManager\providers\<EnrollmentID>\default\Device\<Area>` | The Policy CSP writes its effective values here; ADMX-backed policies also land under `HKLM\SOFTWARE\Policies\...`. Enrollment presence: `HKLM\SOFTWARE\Microsoft\Enrollments\<GUID>` (`EnrollmentType`, `ProviderID` such as `MS DM Server`). |
| Domain / Entra join state | `dsregcmd /status` (`AzureAdJoined`, `EnterpriseJoined`, `DomainJoined`, `MdmUrl`), or `NetGetJoinInformation` / WMI `Win32_ComputerSystem.PartOfDomain` | Show a status banner: *Workgroup / Domain-joined (contoso.local) / Entra-joined / Hybrid / MDM-enrolled (Intune)*. |
| Edition / build | `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion` → `EditionID`, `ProductName`, `DisplayVersion`, `CurrentBuild`, `UBR` | Needed because many policies are **ignored on Home/Pro** (7.3) and because tweaks have build ranges. |
| Tamper Protection / Smart App Control / S-mode | `Get-MpComputerStatus IsTamperProtected`; `HKLM\SYSTEM\CurrentControlSet\Control\CI\Policy\VerifiedAndReputablePolicyState`; edition/`OSProductSuite` | With Tamper Protection on, Defender settings changes via registry/PowerShell fail — show *blocked by Tamper Protection* instead of "applied". Smart App Control blocks unsigned binaries; an unsigned OTW will not run while SAC is on (until April 2026 SAC could not be re-enabled after being turned off without a reset; the 2026-04 CU lifted that). |

### 7.2 The official artifacts (and why OTW should be able to *export* them)

* **Group Policy Objects / LGPO** — Microsoft's Security Compliance Toolkit (SCT 1.0, republished 2026-02-23) ships baseline GPO backups for Windows 11 24H2 and 25H2, Windows 10 22H2, Server 2022/2025 (2602), Edge v139 and Microsoft 365 Apps 2512, plus `LGPO.exe` (apply GPO backups / `.PolicyRules` / `registry.pol` to local policy), `PolicyAnalyzer.exe` (compare baselines/GPOs against local policy) and `SetObjectSecurity.exe`. `registry.pol` is a documented binary format ("PReg" signature `0x67655250`, version DWORD, then `[key;value;type;size;data]` records in UTF-16LE) — OTW can read/write it natively without redistributing `LGPO.exe`.
* **Intune settings catalog / Policy CSP** — the MDM equivalents (`./Device/Vendor/MSFT/Policy/Config/System/AllowTelemetry`, `Experience/*`, `Privacy/*`, `ApplicationManagement/*`, `Update/*` …). Intune **Remediations** (detection + remediation script pairs; detection `exit 1` = issue found → remediation runs; output ≤ 2,048 characters; runs as SYSTEM or the logged-on user; requires Entra/hybrid join + Windows E3/E5 or A3/A5 licences; schedules once/hourly/daily; optional script-signature enforcement) is the enterprise-standard "drift" mechanism — OTW's CLI should be droppable into a Remediation package unchanged (`otw scan --profile X` → exit 1 on drift; `otw enforce --profile X`).
* **Windows Restricted Traffic Limited Functionality Baseline (RTLFB)** — Microsoft's own "maximum privacy" package for Windows 10/11 **Enterprise** and Server. Microsoft's own warnings are the template for OTW's *Paranoid* tier: it "can reduce the functionality and security configuration of your device"; "The Get Help and Give us Feedback links no longer work"; settings must be re-applied after *Reset this PC*; "During update or upgrade of Windows, egress traffic may occur"; and "we do not recommend disabling" Windows Update, Automatic Root Certificates Update or Microsoft Defender Antivirus. The companion document "Manage connections from Windows operating system components to Microsoft services" (updated 2026-02-13) enumerates 33 connection categories (Automatic Root Certificates Update, Cortana/Search, Date & Time, Device metadata, Find My Device, Font streaming, Insider builds, IE, License Manager, Live Tiles, Mail sync, Microsoft Account, Edge, NCSI, Offline maps, OneDrive, Preinstalled apps, Settings > Privacy (23 sub-settings), Software Protection Platform, Storage Health, Sync your settings, Teredo, Wi-Fi Sense, Defender, Spotlight, Store, Apps for websites, Delivery Optimization, Windows Update, Cloud Clipboard, Services Configuration, Widgets, Recommendations) — the authoritative *taxonomy* OTW's privacy catalogue should mirror, with a `source` link per item.
* **Windows 11 25H2 "Remove Default Microsoft Store packages"** — a new first-party device-level policy (`Computer Configuration > Administrative Templates > Windows Components > App Package Deployment > Remove Default Microsoft Store packages from the system`; registry `HKLM\SOFTWARE\Policies\Microsoft\Windows\Appx\RemoveDefaultMicrosoftStorePackages`; also in the Intune settings catalog) that deprovisions a curated list of inbox apps (Sticky Notes, Solitaire, Quick Assist, Xbox, Clipchamp, …) at provisioning/logon events and logs to `AppXDeploymentServer/Operational`. It is **Enterprise/Education only** (Pro excluded), 25H2+, and reportedly may be back-ported. OTW should prefer this policy on eligible SKUs and fall back to `Remove-AppxProvisionedPackage` / `Remove-AppxPackage -AllUsers` elsewhere, and should surface *which mechanism it used*.

### 7.3 Edition gotchas an honest tool must surface

| Policy / behaviour | Home | Pro | Enterprise / Education |
|---|---|---|---|
| `AllowTelemetry = 0` ("Diagnostic data off" / Security) | no (treated as Required) | no (treated as Required) | yes |
| Turn off Microsoft consumer experiences (`DisableWindowsConsumerFeatures`) | ignored | ignored (since 1607) | honoured |
| Do not show Windows tips; Configure Windows Spotlight; Turn off the Store application; Disable all apps from Microsoft Store | ignored | ignored (documented Enterprise/Education-only) | honoured |
| Windows Update for Business deferral / `TargetReleaseVersion` policies | not supported | supported | supported |
| Group Policy editor (`gpedit.msc`) | absent (registry-only) | present | present |
| 25H2 "Remove Default Microsoft Store packages" | no | no | yes (25H2+) |

OTW's catalogue should mark each such tweak with an `editionScope` and show a **"No effect on this edition"** badge rather than pretending it applied (several tools today silently write `DisableWindowsConsumerFeatures` on Pro and users report "ads still there").

### 7.4 Feature-update / enablement-package behaviour

* Windows Setup supports **custom action scripts** during a *media/Setup-based* feature update: `%windir%\System32\update\run\<GUID>\{preinstall,precommit,postuninstall,success,failure}.cmd` (`run` = migrated to future upgrades; `runonce` = one-shot). `success.cmd` is the hook to re-apply tweaks after a 24H2-style upgrade. **But** Microsoft states "Custom actions are not supported for feature updates that are installed via enablement packages" — and 24H2→25H2 and the upcoming 26H2 (build 26300, ~174 KB eKB) *are* enablement packages. So OTW must not rely on `success.cmd` alone: it needs a Task Scheduler task (`AtStartup` + `OnLogon`, plus an event trigger on `Microsoft-Windows-WindowsUpdateClient/Operational` install-success or `Setup` events) that compares stored `CurrentBuild.UBR` / `DisplayVersion` with the live value and runs `otw enforce` when they differ.
* Current servicing state (MS release-health page, 2026-08-11): 24H2 = 26100.9168, 25H2 = 26200.9168, 26H1 = 28000.2704 (new-device-only, not offered as in-place upgrade), 23H2 (22631) still listed. OTW's catalogue `appliesTo` ranges should be expressed on `CurrentBuild` (26100 / 26200 / 28000 / 26300 …) rather than marketing names.

## 8. Enterprise-grade must-haves checklist (with rationale)

Think of two personas reviewing OTW: the **Windows enterprise admin** (Intune/ConfigMgr/GPO; cares about idempotence, unattended runs, exit codes, not fighting policy, and being able to explain every change to a change-advisory board) and the **security auditor** (cares about provenance, integrity, audit trail, least privilege, reversibility, and evidence). Items marked ★ are the ones a naive product owner most often forgets.

### 8.1 Command line & automation

| # | Requirement | Rationale / concrete spec |
|---|---|---|
| 1 | **First-class CLI with stable exit codes and machine-readable output** | `otw scan\|plan\|apply\|enforce\|revert\|export\|health --profile <file> --format json\|table\|csv\|sarif`. Exit codes: `0` compliant/success, `1` drift/partial, `2` failure, `3` invalid args/profile, `4` unsupported platform, `5` reboot required. Mirrors Intune Remediations (`exit 1` = issue found), HotCakeX HSS (`0/1/2`), SysAdminDoc Debloat-Win11 (`0/1/2`). JSON schema published and versioned. |
| 2 | **Unattended / silent mode** | `--silent --accept-risk <level>`; no prompts; no UI thread; `--non-interactive` fails fast on any decision it would otherwise ask about. Every GUI tool in the landscape that gained traction with admins added this later (Win11Debloat `-Silent`, ShutUp10 `/quiet`, Sophia preset files, winutil `-Config -Run`). |
| 3 ★ | **Dry-run / what-if (`plan`)** | Emit the exact registry/service/task/appx/firewall operations that *would* be executed, with current → desired values, before touching anything. Terraform-style plan output; also used by the GUI "what will change" preview. |
| 4 ★ | **Transaction-like apply with automatic rollback on failure** | Apply in ordered steps; each step records its pre-state; on unrecoverable error, unwind steps already applied (like MSI rollback). Log the transaction ID everywhere. |
| 5 | **Idempotence** | Re-running `apply` on a compliant machine changes nothing and exits 0. Essential for scheduled re-enforcement and Intune detection. |
| 6 ★ | **Scheduled re-enforcement** | Optional Task Scheduler task (runs as SYSTEM, `AtStartup`/`OnLogon`/daily + build-change trigger; see 7.4) executing `otw enforce --profile <pinned>`; O&O sells this as *ShutUp10 Premium*. Task must be signed/pinned to a specific profile hash to prevent tampering. |
| 7 | **Machine + user scoping flags** | `--scope machine\|current-user\|all-users\|default-profile\|user:<SID>`; see 8.4. |
| 8 | **Offline / air-gapped operation** | No network access is required for any operation; the catalogue ships inside the binary and can be updated by dropping a signed file. Update-check is opt-in only. |

### 8.2 Safety, reversibility, recovery

| # | Requirement | Rationale / concrete spec |
|---|---|---|
| 9 ★ | **Per-tweak backup of prior state + one-click revert** | Before each tweak: capture registry values (with type & absence), service `Start` type + status, scheduled task enabled state, appx package identity + provisioned state, firewall rule XML, hosts lines, feature state — as a JSON snapshot **and** a `.reg` export for humans. Store under `%ProgramData%\OpenTheWindows\snapshots\<txid>\`. Revert history is a timeline (see §9). Tools without this (Sycnex, W4RH4WK, most one-click "optimizers") are the ones with the worst breakage reputation. |
| 10 ★ | **System Restore point before apply, with the 24-hour limit handled** | `SRSetRestorePoint` (or `Checkpoint-Computer`) silently *skips* if a restore point was created in the last 24 h. Documented override: DWORD `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\SystemRestore\SystemRestorePointCreationFrequency` (minutes; `0` = never skip). OTW should set it temporarily (or to 0 with the user's consent), verify a point was actually created (check sequence number), and warn when System Restore is disabled on the volume (default on many OEM images and small disks). Win11Debloat's `-CreateRestorePoint` documents the same 24 h caveat. |
| 11 ★ | **"Irreversible" gating** | Some actions cannot be undone by OTW (removing provisioned packages that are not in the Store, e.g., some inbox capabilities; deleting event logs; `takeown` on TrustedInstaller keys; disabling Smart App Control; BitLocker/TPM changes). Require `--allow-irreversible` / explicit second confirmation and a distinct badge (SysAdminDoc's `-AllowIrreversibleChanges` pattern). |
| 12 | **Never modify object ACLs/ownership as a "tweak"** | Taking ownership of `WaaSMedicSvc`, `Windows Defender` or CI keys from TrustedInstaller is how many tools "force" changes; it leaves permanent servicing damage and is a top cause of failed cumulative updates. If a change requires it, it belongs in `Breaking` and should be off in every built-in profile. |
| 13 ★ | **Pre-flight checks** | Pending reboot, Windows Update in progress, battery/AC, disk space, S-mode, Tamper Protection, Insider ring, unsupported build, "another tweaker detected" (Sophia refuses to run when others are present), OneDrive Known-Folder-Move active (blocks OneDrive removal), Edge required by WebView2 dependants, domain/MDM managed (7.1). |
| 14 | **Health check** (`otw health`) | Defender real-time on and signatures < N days; updates not paused > X days and last successful install date; Secure Boot; TPM 2.0 present/ready; BitLocker status per volume; UAC on; SmartScreen state; firewall profiles on; System Restore enabled; free disk; pending reboot; Windows activation state; whether the OS build is still serviced (EoS dates from release-health). Report as JSON + human. |
| 15 | **Safe-mode / recovery documentation in-product** | Every profile export includes a "how to undo without OTW" appendix (`.reg` files, `sc config` lines, `Add-AppxPackage -Register` commands, WinRE instructions). |
| 16 | **Support bundle** | `otw support-bundle` → zip with logs, snapshots, health, catalogue version, redacted machine facts (username/hostname/SIDs pseudonymised) for troubleshooting tickets. |

### 8.3 Drift detection, compliance, audit

| # | Requirement | Rationale / concrete spec |
|---|---|---|
| 17 ★ | **`scan` (detect drift) and `enforce` (remediate) as separate verbs** | Detection is read-only, fast, runnable as a non-admin where possible; enforcement is privileged. This is the Intune Remediations / ConfigMgr Configuration Baseline / HardeningKitty Audit-vs-HailMary shape. Report per-tweak `compliant \| drifted \| not-applicable \| managed-by-policy \| blocked \| unknown`. |
| 18 ★ | **Audit trail to Windows Event Log (custom provider) + local JSONL** | Register an event source/ETW manifest ("OpenTheWindows/Operational") at install; write one event per applied/reverted tweak with txid, tweak id, before/after, actor SID, mode (GUI/CLI/scheduled), profile hash. SIEMs (Sentinel, Splunk, Elastic) already collect Event Log; a JSONL file (`%ProgramData%\OpenTheWindows\logs\*.jsonl`) is the offline copy. Note `EventLog.CreateEventSource` needs admin (do it during install / first elevated run). |
| 19 | **Compliance report export** | HTML (human), JSON (native, schema-versioned), CSV (spreadsheet), **SARIF 2.1.0** (each tweak = rule, each drift = result; ingested by GitHub code scanning and many dashboards), and optionally XCCDF/ARF or OSCAL for GRC tooling. |
| 20 ★ | **MDM / GPO / domain awareness** | Detect the management channel (7.1). For each tweak show *managed by your organization* when the effective value comes from a GPO/MDM policy; default behaviour: **do not override**, mark `managed-by-policy`, and offer to *export* the equivalent policy (registry.pol / OMA-URI / settings-catalog JSON) instead. `--override-managed` exists but is loud. |
| 21 | **Signed / verifiable configuration profiles** | Profiles are JSON (or YAML) with a canonical form; sign with a detached signature (minisign/Ed25519 or X.509 via `SignedCms`/JWS). `otw apply` refuses unsigned profiles in `--require-signed` mode; scheduled enforcement pins the profile hash. Publish OTW's own profile-signing public key. |
| 22 | **Catalogue versioning with `appliesTo` and test evidence** | Each tweak: `id`, `since`/`until` build ranges, `editions`, `arch`, `verifiedOn: [{build, date, method}]`, `sources[]`, `policyMapping{gpo, csp, registry}`, `risk`, `reversible`, `restartRequired`, `category`, `level`. Tweaks whose `until` is exceeded by the running build are shown as *unverified on this build* and excluded from `Safe`. This is what prevents the "Copilot registry key stopped working on 24H2" class of failure. |

### 8.4 Scope: per-user vs machine vs all users vs default profile

| Scope | Mechanism | Risks OTW must handle |
|---|---|---|
| Machine (HKLM, services, tasks, provisioned appx, firewall) | direct | Needs elevation. |
| Current user (HKCU) | direct | When elevated, the "current user" is the admin token's user — a UAC-elevated OTW launched from a standard-user session writes to the *admin's* HKCU unless it explicitly targets the interactive user's SID (`HKU\<SID>`, resolved via `WTSQueryUserToken`/explorer.exe owner). |
| All existing users | iterate `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\ProfileList` → for loaded hives write to `HKU\<SID>`; for unloaded profiles `reg load HKU\OTW_<SID> C:\Users\<name>\NTUSER.DAT` → write → `reg unload` | Must dispose all handles (and force GC in .NET) before unload, otherwise unload fails and the profile becomes a *temporary profile* at next logon; skip service accounts and `.bak` entries; roaming profiles may overwrite on logoff; hive locked while the user is logged on. |
| New users (default profile) | `reg load HKU\OTW_Default C:\Users\Default\NTUSER.DAT` (Win11Debloat `-Sysprep` mode; SysAdminDoc `-ExpectedScope AllUsers`). | Same unload discipline; changes only affect *future* accounts; also handle `UsrClass.dat` (HKCU\Software\Classes) for shell-related tweaks. |
| Deprovisioning apps for new users | `Remove-AppxProvisionedPackage -Online` (+ 25H2 policy on Ent/Edu) and add package names to `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Appx\AppxAllUserStore\Deprovisioned\<PFN>` so Update doesn't re-provision. | Not honouring Deprovisioned is why apps come back after feature updates. |

### 8.5 Distribution, provenance and the "unsigned binary" reality

The developer will **not** code-sign the executable. Consequences and mitigations:

| Consequence | Detail | Mitigation |
|---|---|---|
| SmartScreen "Windows protected your PC" | Unsigned, low-reputation downloads trigger the blue SmartScreen dialog until reputation accrues (per file hash — so **every release starts at zero**). | Publish SHA-256 for every artifact; winget manifest (winget accepts unsigned installers/portables but requires `InstallerSha256`, and validation runs Defender/SmartScreen scans; portable installer type supported); explain "More info → Run anyway" in docs; keep a stable filename; encourage users to run `Unblock-File`; sign the *release tag* and artifacts with Sigstore/cosign or minisign so at least authenticity is verifiable. |
| WDAC / AppLocker / Smart App Control environments | Publisher rules are impossible; admins must use hash rules (re-created every release) or sign it themselves. Smart App Control blocks unsigned apps outright. | Ship an **`otw sign-me` guide** + script for organisations to sign the binary and MSI with their internal code-signing cert (`signtool sign /fd sha256 /a ...`) or generate a signed **catalog file** (`Package Inspector` / `New-CIPolicy` workflow) so WDAC trusts it without re-signing the PE; keep the binary a **single self-contained file** so hash rules cover one artifact; publish per-release hashes in a machine-readable file for AppLocker/WDAC hash-rule generation. Since OTW is MIT/permissive, internal re-signing is explicitly allowed — say so in the licence FAQ. |
| No Microsoft Store MSIX | Store submissions require Partner Center identity + Microsoft-signed MSIX; sideloaded MSIX must be signed by a trusted cert. | Provide portable EXE + WiX MSI + winget; provide an *unsigned* MSIX project so orgs can sign/deploy via Intune LOB if they want. |
| Trust / supply chain | Auditors ask "how do I know this binary is the source I read?" | **Reproducible builds** (`<Deterministic>true</Deterministic>`, `ContinuousIntegrationBuild=true`, pinned SDK via `global.json`, Source Link, `PathMap`), **SBOM** (Microsoft `sbom-tool` → SPDX 2.2/3.0 or CycloneDX via `dotnet CycloneDX`), **lock files** (`RestorePackagesWithLockFile` + `RestoreLockedMode` in CI, Central Package Management), `NuGetAudit` + `dotnet list package --vulnerable` in CI, GitHub artifact attestations / SLSA provenance (HotCakeX ships SLSA L3 attestations), Dependabot, CodeQL, VirusTotal scan link per release. |
| Zero telemetry of its own | An anti-telemetry tool that phones home is a credibility killer. | No network I/O by default; opt-in update check that fetches a signed JSON only; document it; make it verifiable (`otw about --network-policy`). |

### 8.6 Product-quality items that are usually forgotten

* **Accessibility & localisation**: UI Automation names for every control (WPF/WinUI 3 expose UIA; Avalonia has UIA support since 11.0), full keyboard navigation, high-contrast theme support, respects system text scaling / high-DPI (PerMonitorV2), dark/light following system; strings in resource files (`.resx`) from day one; the tweak catalogue text itself must be localisable (id-keyed).
* **Documentation per tweak inside the app**: what / why / risk / what breaks / how to revert / official policy path / source links / build evidence.
* **Search + filter** (by text, category, risk, level, state, "changed by OTW", "managed by org", "restart required").
* **"Explain what changed" diff view** after apply, and side-by-side *current vs desired* before apply.
* **Restart / sign-out / Explorer-restart required** indicators, with a "restart later" queue.
* **Multi-language & multi-SKU testing matrix** published (Home/Pro/Ent/Edu × 24H2/25H2/26H1 × x64/ARM64).
* **Elevation model**: run un-elevated for browsing/scan; request elevation (UAC) only for apply; or install an optional service for scheduled enforcement (HotCakeX uses a SYSTEM service `QuantumRelayHSS`). Never auto-elevate on launch. Show which token/user each scope will affect.
* **Uninstall leaves the machine as configured** (do not silently revert on uninstall) but offers "revert everything OTW ever changed" as an explicit option; uninstall removes tasks/services/event source it created.

### 8.7 The ten features a naive product owner is most likely to forget (ranked)

1. **Drift detection + scheduled re-enforcement with a build-change trigger** (Windows and feature/enablement updates silently revert things; O&O charges for this; enablement packages skip `success.cmd`).
2. **MDM/GPO/domain awareness** — detect the management channel, show "managed by your organization", don't fight it, and *export* the equivalent policy artefacts (registry.pol / OMA-URI / settings-catalog JSON) instead.
3. **Per-tweak pre-state snapshot + transactional apply with automatic rollback**, plus an "undo without OTW" script export.
4. **Restore point handling that actually works** — the 24-hour skip (`SystemRestorePointCreationFrequency`), disabled-System-Restore detection, and verification that a point was created.
5. **Scope model** — current user vs *interactive* user vs all existing users vs Default profile (hive loading with proper unload) vs machine, plus the `Deprovisioned` key for AppX.
6. **Edition/build truth** — mark tweaks that are ignored on Home/Pro (`AllowTelemetry=0`, consumer features, Store policies) and tweaks whose registry keys died on a given build (`appliesTo`, `verifiedOn`).
7. **Audit trail in the Windows Event Log (custom provider) + JSONL + compliance exports (JSON/CSV/HTML/SARIF)**.
8. **Verify-after-write** to expose Tamper Protection / UCPD / policy blocks instead of reporting "applied" (ShutUp10 3.3 does this).
9. **Unsigned-binary mitigations** — reproducible builds, SBOM, published hashes, winget manifest, artefact attestations, and an "organisations may re-sign / catalog-sign this" guide for WDAC/AppLocker/Smart App Control.
10. **Pre-flight guards for the known killers** — WebView2 dependants before touching Edge, OneDrive Known-Folder-Move before removing OneDrive, service dependants before disabling services, pending reboot / WU-in-progress, S-mode, other tweakers present.

Runner-ups: accessibility/localisation from day one; a `health` verb; a support-bundle exporter; "reset to Windows defaults" as a first-class action distinct from "revert my changes"; per-tweak documentation with sources inside the app.
