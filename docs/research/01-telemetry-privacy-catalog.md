**Project:** Open The Windows (C#/.NET, GUI + CLI)  
**Research date:** 2026-08-16  
**Target OS:** Windows 11 23H2 (22631), 24H2 (26100), 25H2 (26200) — Home / Pro / Enterprise / Education / IoT Enterprise (Enterprise LTSC 2024 = 24H2 base). Windows 10 differences noted only where relevant.  
**Sourcing rule:** every row cites at least one source (`S#` → see *Sources* at the end). ## 0. How to read this document

### 0.1 Columns used in the control tables

| Column | Meaning |
|---|---|
| **ID** | short kebab id (stable; suggested as the app's internal `ControlId`) |
| **Name / what it stops** | user-facing name and the data flow or behaviour that is stopped |
| **Mechanism** | exact registry `HIVE\Key` + `ValueName` + type + value; **or** service name + startup type; **or** scheduled task path; **or** appx package; **or** cmdlet/env var. `POL:` = a *policy* key (`…\Policies\…` or `…\CurrentVersion\Policies\…`; greys out the UI, wins over the user preference, is refreshed by Group Policy/MDM). `PREF:` = the *preference* key the Settings app itself writes (what a consumer toggle does). `CSP:` = Policy CSP OMA-URI (Intune/MDM). |
| **Kind** | Policy / Pref / Service / Task / Appx / Cmd / Env / Firewall / CSP-only |
| **Scope** | HKLM (machine) / HKCU (per user — the app must apply per profile and/or to the Default User hive for new users) / both |
| **Editions & versions** | which SKUs honour it; minimum Windows version |
| **Revert** | how to undo (delete value = "not configured"; or the enable value) |
| **Side effects / risk** | functional breakage; enterprise dependencies |
| **Level** | recommended default profile: **Basic** = zero functional loss (safe for everyone) · **Balanced** = cosmetic/minor loss · **Strict** = noticeable loss of convenience features · **Paranoid** = accepts real functional loss; never on managed devices · **Never** = do not offer as a "privacy" toggle (security regression or breaks the OS) |

### 0.2 Policy keys vs preference keys — why the app must know both

* Windows components read **policy** locations first (`HKLM\SOFTWARE\Policies\…`, `HKCU\Software\Policies\…`, `HKLM|HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\…`). If a policy value exists it wins, the corresponding Settings toggle is greyed out with "Some of these settings are managed by your organization", and a Group Policy / MDM refresh may rewrite it (S58, S59).
* **Preference** locations (`HKCU\Software\Microsoft\Windows\CurrentVersion\ContentDeliveryManager`, `HKCU\…\CapabilityAccessManager\ConsentStore`, `HKCU\Software\Microsoft\Siuf\Rules`, …) are what the Settings app writes; the user can flip them back at any time and nothing greys out.
* **Recommended app behaviour:** *Consumer mode* → write PREF keys (UI stays usable, no "managed by organization" banner). *Enterprise / "lock" mode* → write POL keys **and** the local `Registry.pol` (see §18.2) so the setting is visible in `gpedit.msc` and survives `gpupdate` on the local layer. Always read POL first when *displaying* state; if a POL value exists that the app did not write, show "managed" and do not fight it (§18.1).
* Home edition: `gpedit.msc` is absent but **the registry policy keys are still honoured by most components** (the ADMX consumer is the component, not the editor). Exceptions are noted per row (e.g. `AllowTelemetry=0`, several CloudContent policies are Enterprise/Education-only *by design*; the CSP tables state "❌ Pro" for those — S4).

### 0.3 The plumbing (what actually sends data)

| Component | Role | Notes |
|---|---|---|
| **DiagTrack** ("Connected User Experiences and Telemetry", `diagtrack.dll` in svchost) | Collects ETW diagnostic events, batches and uploads them to `v10.events.data.microsoft.com` / `v10c.events.data.microsoft.com` / `self.events.data.microsoft.com`; also collects *diagnostic logs* when Optional level is on | The level is decided by `AllowTelemetry`; the service is *not* what decides the level. Disabling the service is a blunt instrument (S2, S36, S49). |
| **dmwappushservice** ("Device Management WAP Push message Routing Service") | Routes WAP-push/OMA-DM messages; older DiagTrack builds declared a dependency on it, which is why many tools list it as "telemetry" | Not a telemetry uploader; disabling can break MDM enrollment/sync. **UNVERIFIED-MS** as telemetry. |
| **DeviceCensus.exe** | Periodic census of hardware/software used by Windows Update / WUfB reports | Runs from `\Microsoft\Windows\Device Information\Device`; WUfB reports need it (S48). |
| **Windows Error Reporting** (`WerSvc`, `wermgr.exe`, `WerFault.exe`) | Crash metadata + dumps to `watson.telemetry.microsoft.com`, `umwatsonc.events.data.microsoft.com`, `*watcab0*.blob.core.windows.net` (S2) | Independent of DiagTrack; own policies (§3). |
| **OneSettings** (`settings-win.data.microsoft.com`, `settings.data.microsoft.com`) | Remote *configuration* download for Windows components; does not upload diagnostic data. Microsoft: "Don't block access to this endpoint" (S2). | `DisableOneSettingsDownloads` exists but has documented side effects (S3, S48). |
| **Compatibility Appraiser / CEIP tasks** | `CompatTelRunner.exe` (Application Experience tasks) collects app-compat inventory; CEIP tasks (Consolidator, UsbCeip, KernelCeipTask…) are dormant when `CEIPEnable=0` (S24, S67, S68) | See §2 and §16. |
| **ContentDeliveryManager (CDM)** | Downloads Spotlight images, Start/lock-screen/Settings suggestions, "silently installed" promo apps | Controlled per user by `SubscribedContent-*` etc. (S1 §25, S67–S70). |
| **Windows Push Notification Service (WNS)** | Cloud notification channel used by apps *and by MDM for real-time actions* | Do not block wholesale (S12, S36). |
| **Edge** | Since Edge 122 diagnostic data is separately controlled by `DiagnosticData` on Windows 10/11 (previously it followed the Windows level) (S42); in the EEA collected separately from Windows since 2024-03-06 (S2) | §14 |
| **Office / M365 Apps, OneDrive, Teams, dev tools, GPU drivers** | Own telemetry pipelines, own controls (§15) | Adjacent scope |

### 0.4 Windows diagnostic data levels (authoritative — S2, S3)

| Value | Name (Win 11 UI) | Old name | Who honours it |
|---|---|---|---|
| 0 | Diagnostic data off | Security | **Enterprise, Education, IoT Enterprise, Server only.** "Using this setting on other devices is equivalent to setting the value of 1" (S3). On Home/Pro it silently behaves as Required. UI never shows "off": "If the Security option is configured by using Group Policy or the Registry, the value will not be reflected in the UI" (S1 §18.16). |
| 1 | Required diagnostic data | Basic | All editions. Default since Windows 10 1903 and on all Windows 11. Setting it via policy disables the "Send optional diagnostic data" toggle. |
| 2 | Enhanced | Enhanced | **Not available on Windows 11** (S2) — use `LimitDiagnosticLogCollection` + `LimitDumpCollection` instead. |
| 3 | Optional diagnostic data | Full | All editions. Adds browsing/app-usage/inking-typing data, full & heap dumps, diagnostic logs. |

Microsoft's own minimum for organisations relying on Windows Update / WUfB reports / Autopatch / Intune update reports / Endpoint analytics is **Required (1)**, not 0 (S2, S48).

### 0.5 Recommended level profiles (summary)

| Profile | Diagnostic data | Cloud content / ads | Search | AI | App permissions | Network |
|---|---|---|---|---|---|---|
| **Basic** | Required (1) via PREF, no policy; feedback = never; tailored experiences off; advertising ID off; improve inking/typing off; WER left default | All Start/Settings/lock-screen suggestions off (PREF) | Bing/web *suggestions* off in Start (only loss: web results in Start) | Recall snapshots off (already default), Copilot app left installed but unpinned | user stays in control | nothing |

### 0.6 At a glance

* **248 catalogued control rows** (§1–§15; ~235 actionable, the rest are informational/"see" rows or Insider watch-list items) + **24 scheduled tasks** + **21 services** (§16) + **22 dangerous practices** (§17). 66 fields are tagged UNVERIFIED / UNVERIFIED-MS.
* **Highest-value, zero-regret controls (Basic profile):** `dd-allowtelemetry-pref` (Required), `dd-limit-diag-logs` + `dd-limit-dumps`, `dd-feedback-freq`, `dd-tailored-pref`, `ads-advid-pref`, `ads-track-progs`, `ads-lang-list`, `inp-tipc` + `inp-personalization-pref`, `srch-bing-suggestions`, `srch-history`, `srch-highlights`, `cc-cdm-*` (all Start/Settings/lock-screen/welcome suggestions), `cc-cdm-silent-installs`, `cc-start-iris`, `ah-upload` + `ah-publish`, `ai-recall-snapshots`, `sync-clipboard-cloud`, `edge-diagnostic-data`=1 + `edge-personalization` + `edge-ntp-content`/`edge-spotlight`/`edge-shopping`, `ceip-sqm` + `ceip-ait` + CEIP tasks, `sec-sample-submission` (=prompt/never — keeps MAPS on).
* **Highest-impact enterprise policies (Balanced/Strict, Ent/Edu):** `dd-allowtelemetry-pol`=0/1, `cc-consumer-features`, `cc-cloud-optimized`, `cc-spotlight-all`, `srch-web-results-pol`, `ai-recall-allow`, `ai-click-to-do`, `ai-copilot-applocker`, `sync-settings-pol`, `wer-disable-pol`, `store-insider`.
* **Never offer as "privacy":** hosts/DNS blocking of Microsoft domains, `sec-defender-off`, `store-root-certs`, `store-windows-update`, `store-wlidsvc`, `store-licensemanager`, `srch-disable-ui`, `store-live-tiles-wns` on managed devices, `dd-diagtrack-svc` on managed devices (see §17).

## 18. Enterprise considerations

### 18.1 MDM / Intune interplay (Policy CSP)

* Intune / MDM writes Policy CSP values into `HKLM\SOFTWARE\Microsoft\PolicyManager\current\device\<Area>\<PolicyName>` (`value` REG_DWORD/REG_SZ) and the per-provider store `HKLM\SOFTWARE\Microsoft\PolicyManager\providers\<EnrollmentGUID>\default\Device\<Area>\<PolicyName>`; user-scope policies under `…\PolicyManager\current\<UserSID>\…`. **UNVERIFIED-MS as a documented contract** (Sophia reads/removes `…\PolicyManager\current\device\Start\HideRecommendedSection`, `…\default\NewsAndInterests\AllowNewsAndInterests`); Microsoft documents that ADMX-backed policies delivered by MDM cause the Policy CSP to "update the device's registry per the ADMX policy definition" — i.e. they land in the same `Policies` keys as Group Policy (S58). Non-ADMX CSP policies (e.g. `System/AllowExperimentation`, `Privacy/LetAppsAccess*` are ADMX-backed; `Experience/AllowSyncMySettings` is not) are read by components from the PolicyManager store.
* **Detection the app should do:** (1) `IsDeviceRegisteredWithManagement()` (mdmregistration.dll, S64) or enumerate `HKLM\SOFTWARE\Microsoft\Enrollments\<GUID>` with `EnrollmentType`/`ProviderID` (UNVERIFIED-MS as API; widely used); (2) `dsregcmd /status` → `AzureAdJoined`, `EnterpriseJoined`, `DomainJoined`, `TenantId`, `MdmUrl` (S66); (3) `NetGetJoinInformation()` for AD join state (S65) and `NetGetAadJoinInformation()` for Entra join; (4) MDE onboarding (`Sense` service). If a control's PolicyManager value exists (or the `Policies` value exists and the app did not write it), render it **"Managed by your organization — read-only"** and refuse to override. `MDMWinsOverGP` (S35) means MDM policy also removes conflicting scripted values at every sync — fighting it is pointless.
* Enterprise defaults to bake in: keep `AllowTelemetry` ≥ 1 and DiagTrack running when Intune/WUfB reports/Autopatch/Endpoint analytics/MDE are present; keep OneSettings; keep WNS.

### 18.2 Group Policy vs raw registry — Registry.pol and LGPO

* Administrative-template settings live in `Registry.pol` files: `%SystemRoot%\System32\GroupPolicy\Machine\Registry.pol` and `…\GroupPolicy\User\Registry.pol` (format documented: header `PReg`, records `[key;value;type;size;data]`, `**del.`/`**DeleteValues` markers — S59). The Group Policy client applies them to the registry at logon/boot and every refresh (`gpupdate`, ~90 min ± 30 on domain members).
* A value written **only** to `HKLM\SOFTWARE\Policies\…` (a) is honoured by the component immediately, (b) is **not** shown in `gpedit.msc` (it reads Registry.pol), and (c) on a domain-joined machine is overwritten at the next refresh **if any domain GPO configures the same value** (domain GPOs process after local — LSDOU). Values that no GPO touches generally survive `gpupdate` (the Registry CSE only cleans up values it previously applied), but a *domain-enforced* setting always wins → the app must show it as managed. Read RSoP via WMI `root\RSOP\Computer` `RSOP_RegistryPolicySetting` (or parse `gpresult /x`) to learn whether a value is domain-sourced.
* To make a local setting *first-class* (visible in gpedit, re-applied by the local GPO layer): write it into `Registry.pol` **and** the registry, then bump the GPO version. Options for a C# app: (1) **`IGroupPolicyObject`** COM (`gpedit.h`, CLSID `{EA502722-A23D-11d1-A7D3-0000F87571E3}`): `OpenLocalMachineGPO(GPO_OPEN_LOAD_REGISTRY)` → `GetRegistryKey(GPO_SECTION_MACHINE|USER)` → `RegSetValueEx` under that hive handle → `Save(bMachine, bAdd, REGISTRY_EXTENSION_GUID, appGuid)` (S56; single-threaded apartment required). (2) **`LGPO.exe`** from the Security Compliance Toolkit (`LGPO.exe /t file.txt` LGPO-text, `/m|/u file.pol`, `/parse /m Registry.pol` to export) — redistribution rules apply (S57; Sophia ships it, S69). (3) Parse/emit `Registry.pol` yourself (format S59; reference implementations: PolicyPlus (C#/VB, open source), PolicyFileEditor PowerShell module). After writing, call `RefreshPolicyEx(TRUE, RP_FORCE)` or run `gpupdate /target:computer /force`.
* Home edition: no `gpedit.msc`, but the GP client (`gpsvc`) still exists and Registry.pol *is processed*; the `IGroupPolicyObject` route works. Some ADMX-only settings are ignored by Home components (documented per row).
* Reversibility contract: store the previous value **and** the previous "who owns it" (unset / user pref / local GPO / domain GPO / MDM) so *Undo* can put back exactly that state; never delete a value the app did not create.

## 19. Windows Restricted Traffic Limited Functionality Baseline (RTLFB) — summary and side effects (S1)

* What it is: a downloadable Group-Policy-based package (per Windows version) that applies **all** settings in "Manage connections from Windows operating system components to Microsoft services" (sections 1–33) so that an *Enterprise* device generates almost no egress to Microsoft. It ships GPO backups + scripts; must be applied **offline**, not from `windows\system32`, ideally at imaging time; must be re-applied after *Reset this PC*; egress still occurs during update/upgrade.
* Contents (by section): 1 root-cert auto-update off · 2 Cortana/search off + `SearchHost.exe` firewall block · 3 time sync off · 4 device metadata off · 5 Find My Device off · 6 font providers off · 7 Insider off · 8 IE tuning · 9 License Manager service off · 10 live tiles/WNS off · 11 Mail off · 12 MSA sign-in assistant off · 13 Edge (legacy + Chromium) hardening · 14 NCSI off · 15 maps off · 16 OneDrive off · 17 preinstalled apps removed · 18 all Settings > Privacy toggles forced off (advertising ID, location, camera, mic, notifications, speech, account info, contacts, calendar, call history, email, messaging, phone, radios, other devices, feedback/diagnostics = 0, background apps, motion, tasks, app diagnostics, inking/typing, activity history, voice activation, feeds) · 19 KMS AVS off · 20 storage-health model updates off · 21 settings sync off · 22 Teredo off · 23 Wi-Fi Sense (legacy) · 24 Defender MAPS/samples off, definitions from file share only, MSRT reporting off, SmartScreen off · 25 Spotlight/personalised experiences off · 26 Store off · 27 apps-for-websites off · 28 Delivery Optimization = 99 · 29 Windows Update disconnected · 30 cloud clipboard off · 31 OneSettings off · 32 Widgets off · 33 Recommendations off.
* Stated side effects (Microsoft): reduced security ("Windows Update, Automatic Root Certificates Update, and Microsoft Defender Antivirus … we do not recommend disabling any of these"), Get Help / Give us Feedback links stop working, only the allow-listed endpoints (`activation-v2.sls.microsoft.com`, `crl.microsoft.com/pki/crl/*`, `ocsp.digicert.com`, `www.microsoft.com/pkiops/*`) remain; CRL/OCSP traffic cannot be disabled; Insider upgrade forces Optional diagnostics.
* For the app: use RTLFB as the *authoritative key list*, but ship it as **Paranoid preset with the update/security items stripped** and a clear "lab-only" label.
