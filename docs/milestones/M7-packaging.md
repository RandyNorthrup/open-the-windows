# M7 — Packaging and release

## Goal

Portable ZIP, MSI (WiX 7), winget manifest, release workflow with SBOM,
SHA-256 sums, GitHub build-provenance attestations, framework-dependent
variant (Q3), and the "re-sign / WDAC" guide. No code signing (ADR 0003).

## Preconditions

M6 certified. Read: ADR 0003; research 06 §G (packaging); PLAN §9, §10.

## Deliverables

- `installer/OpenTheWindows.wixproj` (WiX 7 SDK-style, `wix` dotnet tool
  pinned in `.config/dotnet-tools.json`): per-machine, `ProgramFiles64Folder\Open the Windows`,
  stable `UpgradeCode` GUID (generate once, commit, never change), `MajorUpgrade`
  with `Schedule="afterInstallInitialize"`, components for App + CLI, Start
  menu shortcut, optional feature "Add otw to PATH", Event Log source
  registration (`util:EventSource` or a deferred custom action running
  `otw eventlog install`), ProgramData `OpenTheWindows` folder with ACL, ARP
  entries (publisher "Open The Windows contributors", URLs), silent install
  `/qn`, `MSIINSTALLPERUSER=0`. Uninstall keeps journals (documented) unless
  `REMOVEDATA=1`.
- `build/package.ps1`: publish (x64+arm64), zip, MSI x64 (arm64 MSI if WiX
  supports the RID), SBOM, `SHA256SUMS.txt`, version from `git describe` or `-Version`.
- `packaging/winget/RandyNorthrup.OpenTheWindows.yaml` (+ installer/locale
  manifests) generated by `build/winget-manifest.ps1` from the release assets
  (installer type `wix`/`zip` portable, SHA-256, `InstallerSwitches.Silent`).
- `.github/workflows/release.yml`: on tag `v*`: quality gates → package →
  `actions/attest-build-provenance` (SHA-pinned) for every asset → GitHub
  Release with CHANGELOG section as notes, assets, SBOM, SHA256SUMS →
  (manual) winget PR instructions in the job summary. Actions SHA-pinned.
- Framework-dependent variant: `OpenTheWindows-<v>-win-x64-fdd.zip` requiring
  .NET 10 Desktop Runtime; MSI bundles self-contained by default (decision Q3).
- Docs: `docs/install.md` (all channels, verify hashes/attestations, silent
  install, uninstall, data locations), `docs/enterprise.md` §"Re-sign and
  allow-list" (signtool, WDAC/AppLocker hash rules, Intune Win32 app packaging
  with detection rule = `otw.exe` version), README "Installation" replaced.

## Tests / verification

- Install MSI on the VM (silent) → `otw --version` on PATH (if feature
  selected) → Event Log source exists → uninstall → files gone, journals kept.
- Upgrade test: install v(n) then v(n+1) MSI → single ARP entry.
- `winget validate --manifest packaging/winget` passes; `winget install
  --manifest` on the VM works.
- `gh attestation verify <asset> --repo RandyNorthrup/open-the-windows` passes
  for a test tag (`v0.0.1-test`, deleted afterwards).
- Reproducibility: two CI builds of the same commit produce identical
  `otw.exe` hash (Deterministic + ContinuousIntegrationBuild + locked restore);
  record the result honestly (WPF may not be byte-identical — document).

## Acceptance

MSI install/upgrade/uninstall verified on Home + Pro images; winget manifest
validates; attestations verify; release workflow green on a test tag;
`docs/certification/M7.md`.
